# Design System: UIUX Workbench

## Overview

**Creative North Star: "The Quiet Canvas"**

The Workbench is a review desk laid around a running View. Chrome is graphite in both themes and steps back: hairline-separated panels, a calm 13px UI voice, and no color anywhere unless that color is doing a job. The canvas is generous and slightly darker than the panels. The previewed View sits on it as a crisp, lightly lifted frame, and it is the only full-color object on the screen. That is the point. When a reviewer glances at the screen, the eye lands on the thing being judged, never on the tool.

Two inks are allowed to touch the canvas, and they never swap jobs. **Iris** violet, taken from the favicon's `#a78bfa`, means *you are here*: the current selection, keyboard focus, and the one primary action in a region. **Marker** magenta means *a human said something here*: comment pins, the comment tool, the composer, and comment counts. Status colors (leaf green, caution yellow, fault red, notice blue) appear only in badges, icons and alerts. Green means success and nothing else.

The signature move is **the annotation layer**. Figma-like teardrop pins float above the live View on Widgets that the iframe itself resolved. A click opens an inline bubble. Each Widget answers with a precise blueprint label: a 12px mono chip naming the Widget type and id, plus its rendered dimensions. That blueprint register (mono identities, hairline rules, measured numbers) continues into the Inspector, Spec and Evidence surfaces, where the reviewer checks facts. Everywhere else the chrome stays plain Nuxt UI, tuned rather than costumed.

Rejected outright: the default Nuxt UI admin-template look (green primary, card soup, 8px badges), neon-on-black "hacker" dev-tool styling, AI-product gloss (gradients, glassmorphism, sparkles, violet glow), and emoji used as icons.

**Key Characteristics:**
- Graphite chrome with a barely-there violet cast (hue 286, chroma ≤ 0.012), designed for light and dark themes as equals.
- One accent (Iris) for selection, focus and primary action. One annotation ink (Marker) for human comments. Status hues for status only.
- The View is the only colorful region. The canvas is a recessed neutral ground with an optional faint dot grid.
- Type has a 12px floor, a 13px UI default and 14px reading text, with CJK-aware stacks and line heights for zh-TW.
- Mono is reserved for identities, revisions, dimensions and codes. It is the blueprint register.
- Hairlines separate regions. Shadows exist only on things that float: the View frame, pins, bubbles, popovers.
- Workbench chrome theme and locale are independent of the Preview render context, always.

## Colors

The palette is restrained: graphite neutrals carry everything, Iris violet marks the reviewer's own position and action, Marker magenta marks human annotation, and four status hues report state.

### Primary
- **Iris** (`iris-600` light / `iris-400` dark; `iris-400` is exactly the favicon `#a78bfa`): selection outline on the canvas, the selected row in the Widget tree and lists, keyboard focus rings, active tool in the canvas tool palette, and at most one solid primary button per region ("Comment", "Resolve", "Save"). Light theme uses the deeper `iris-600` (#7545d3) so white text and violet text both clear AA. Dark theme uses the favicon violet itself with graphite-900 text. Hover deepens in light (`iris-700`) and brightens in dark (`iris-300`). It never fades with opacity.

### Secondary
- **Marker** (`marker-700` text and badges, `marker-600` pin fill in light / `marker-400` for both in dark): comment pins, the comment tool when active, the dashed hover outline in comment mode, the composer's send affordance, thread-count badges, and Review `open` status. Magenta was chosen because it is the classic markup and redline ink and is the one hue family not already claimed by violet or any status. Registered as the Nuxt UI theme color `annotation`.

### Tertiary
- **Leaf** (`leaf-700` / `leaf-400`): success only. Checks passed, evidence captured, Review `resolved`, Decision `decided`, `implementation-ready`. A softened green (chroma 0.11–0.14), so it never reads as a neon terminal.
- **Caution Yellow** (`caution-yellow-800` / `caution-yellow-400`): warnings, stale evidence, stale or off-screen anchors, Decision `pending`, translation reminders.
- **Fault Red** (`fault-red-700` / `fault-red-400`): errors, invalid anchors, invalid Variants, failed captures, broken adapter sets, destructive confirmation.
- **Notice Blue** (`notice-blue-700` / `notice-blue-400`): Review `ready-for-review` ("waiting for a human verdict") and neutral informational alerts. Nothing else.

### Neutral
- **Graphite** (`graphite-0`…`graphite-950`, hue 286): all chrome.
  - Light: panels `graphite-0`, sidebar hover and section wash `graphite-50`, elevated fills `graphite-100`, accented fills `graphite-200`, hairlines `graphite-200` (muted `graphite-150`), control boundaries `graphite-450`.
  - Dark: panels `graphite-900`, muted `graphite-850`, elevated `graphite-800`, accented `graphite-750`, hairlines `graphite-750` (muted `graphite-800`), control boundaries `graphite-500`.
  - Text: default `graphite-800` / `graphite-200`; highlighted `graphite-950` / white; muted `graphite-600` / `graphite-400`; dimmed `graphite-500` / `graphite-450`.
- **Canvas ground**: `graphite-100` in light, `graphite-950` in dark. It is always one step recessed from the panels, so the View frame reads as an object placed on a desk.

### Named Rules

**The One Colorful Thing Rule.** The View inside the frame is the only full-color region on screen. If a chrome element is colored, it must be selection, focus, the one primary action, an annotation, or a status. Otherwise it is graphite.

**The Single Violet Rule.** Iris means "you": your selection, your focus, your next action. One solid Iris button per region at most. Iris is never decoration, never a status, never a gradient, and never a glow.

**The Marker Rule.** Magenta belongs to human annotation. Pins, the comment tool, comment counts and the `open` badge. Nothing else may borrow it, and annotation never uses violet.

**The Green Means Done Rule.** Leaf green appears only when something succeeded or closed: passed, captured, resolved, decided, ready. Never for navigation, selection, links or "active".

**The No-Opacity-Hover Rule.** Hover and active states move one ramp step (light: darker; dark: lighter). They never lower opacity on a filled control, which would drop text contrast below AA.

## Typography

**Body Font:** Inter (variable, self-hosted at build time), falling back to the system UI stack, then to PingFang TC / Noto Sans TC / Microsoft JhengHei for Han glyphs
**Label/Mono Font:** JetBrains Mono (slashed zero on), falling back to SF Mono / Menlo / Consolas

**Character:** One quiet workhorse sans carries every role, the same register as the Figma reference. A mono with unambiguous `0/O` and `1/l/I` carries identities, because reviewers read and copy UUIDs, revisions and Widget ids. In zh-TW, Latin runs stay in Inter and Han characters fall through to the platform's Traditional Chinese UI face. No webfont is ever downloaded for CJK.

### Hierarchy
- **Display** (600, 24px, 32px): Overview headline counts and empty-state titles only. At most one per screen.
- **Headline** (600, 18px, 26px): page titles: Overview, Reviews, a View's name in its header, Workspace settings.
- **Title** (600, 15px, 22px): panel and section titles, the thread title in a bubble, dialog titles.
- **Body** (400, 14px, 22px): Review messages, Spec prose, Decision text, alert descriptions. Prose measure is capped at 68ch.
- **UI** (400, 13px, 20px; 500 for buttons and active tabs): the default for controls, list and tree rows, tabs, inputs, menus and table cells. Nuxt UI's `text-sm` is retuned to this size.
- **Label** (500, 12px, 16px): field labels, badges, Kbd, counts, timestamps, helper text. **12px is the floor; nothing renders smaller.**
- **Mono** (400, 12px, 16px): ids, revisions, dimensions, change domains, diagnostic codes, evidence digests (truncated middle with a copy button). Sentence or literal case, never uppercase-tracked.

**zh-TW adjustments:** line heights grow by about 2px at every step (UI 13/22, label 12/18, body 14/24), letter-spacing is reset to 0, and labels never truncate mid-word. They wrap to two lines or get a tooltip. Inputs on touch layouts render at 16px so iOS does not zoom.

### Named Rules

**The 12px Floor Rule.** No text below 12px, in any locale, at any density. This includes badges, counts, timestamps and canvas chips. Nuxt UI's `xs`/`sm` badge sizes are re-mapped in theme config so the floor cannot be bypassed.

**The Blueprint Label Rule.** Mono appears only where the content is an identity or a measurement: `#checkout-submit`, `rev 7f3d…a91c`, `1280 × 800`, `content[0]`. Never for headings, buttons or prose, and never as an uppercase-tracked "eyebrow" label.

## Layout

**Spatial model: an application shell on Nuxt UI's dashboard primitives.** `UDashboardGroup` holds a collapsible, resizable left `UDashboardSidebar`, then the canvas (`UDashboardPanel`), then a resizable right panel (`UDashboardPanel` with `resizable`). A 48px `UDashboardNavbar` holds breadcrumbs and global actions. Scrolling happens inside panels, never at page level, except on mobile.

**Rhythm:** 4px base. Controls are 32px tall at desktop density with 8px internal gaps. Panels pad 12px horizontally (16px on the Overview and Reviews pages). Stacks use 8px within a group and 16px between groups. A section heading has 16px above it and 8px below. Tree and list rows are 28px (compact desktop) or 32px (comfortable). On coarse pointers every interactive target grows to 44px through one theme variable (`--wb-target`).

**Device classes and breakpoints** (Tailwind defaults):

| Class | Width | Shell |
|---|---|---|
| Desktop | ≥ 1280px (`xl`); FHD 1920 primary | Sidebar 264px (collapsible to a 56px rail, resizable 220–360), canvas flexible, right panel 340px (resizable 300–440). At 1920 with both open, the canvas is about 1300px and a 1280×800 View fits at about 95%. |
| Tablet | 1024–1279px (`lg`) and portrait 768–1023 (`md`) | Sidebar collapses to the 56px icon rail (landscape) or a slideover (portrait). The right panel becomes a `USlideover` opened on demand. Thread bubbles stay on the canvas. Touch targets are 44px. |
| Mobile | < 768px | Single column. A 48px top bar and a 56px bottom navigation (`UNavigationMenu` horizontal) for Overview / Views / Flows / Reviews. View pages switch between Spec, Comments and Preview with `UTabs`. Threads open in a `UDrawer` bottom sheet. No structural editing. |

**Canvas:** the frame always renders the iframe at its canonical logical viewport size and scales only the outer presentation layer. Fit-to-canvas keeps 24px of gutter on desktop and 12px on tablet and mobile. Zoom steps are 25 / 50 / 67 / 75 / 90 / 100 / 125 / 150 / 200%. The dot grid (1px dots at a 16px pitch, `--wb-canvas-dot`) shows only at ≥ 50% zoom, and is the canvas's only texture.

### Named Rules

**The Canvas First Rule.** At FHD the canvas must keep at least 60% of the viewport width with both side panels open. Any new panel content scrolls inside its panel rather than widening it.

**The Same Place Rule.** A thing lives in one place per device class. Comments are pins plus bubbles on the canvas everywhere, the thread list lives in the right panel (desktop) or a slideover or sheet (tablet and mobile), and the Reviews inbox is a page. They never appear in duplicate side-by-side panels.

## Elevation & Depth

The chrome is flat, and only floating things cast shadows. Panels sit on one plane, separated by 1px hairlines. The canvas is one tonal step recessed. Shadows mark four things that float above the work: the View frame (lifted off the desk), pins (above the View), bubbles and popovers (above pins), and modals or slideovers. In dark mode, shadows are paired with a 1px graphite-750 ring, because a black shadow alone vanishes on a dark ground.

### Shadow Vocabulary
- **Frame lift** (light: `0 0 0 1px oklch(16% 0.006 286 / 0.08), 0 2px 6px oklch(16% 0.006 286 / 0.06), 0 12px 32px -8px oklch(16% 0.006 286 / 0.12)`; dark: `0 0 0 1px var(--color-graphite-750), 0 16px 40px -8px oklch(0% 0 0 / 0.55)`): the Preview frame only.
- **Pin** (`0 0 0 2px var(--ui-bg), 0 1px 3px oklch(0% 0 0 / 0.28)`): comment pins. The 2px panel-colored ring separates the pin from any View content beneath it.
- **Overlay** (light: `0 1px 2px oklch(16% 0.006 286 / 0.06), 0 8px 24px -4px oklch(16% 0.006 286 / 0.14)`; dark: `0 0 0 1px var(--color-graphite-750), 0 12px 32px -4px oklch(0% 0 0 / 0.6)`): composer and thread bubbles, popovers, menus, tooltips, toasts.
- **Modal** (light: `0 24px 64px -12px oklch(16% 0.006 286 / 0.25)`; dark: ring plus `0 24px 64px -12px oklch(0% 0 0 / 0.7)`): `UModal`, `USlideover`, `UDrawer`.

### Named Rules

**The Hairline Rule.** Regions separate by a single 1px `--ui-border` line or by whitespace, never by nested boxes. A card inside a panel inside a panel is a defect.

**The Float-Only Shadow Rule.** If it does not move above something else, it has no shadow.

## Shapes

Small and exact. Controls, inputs, menus and list or tree selection use 6px (`rounded-md`; `--ui-radius` stays 0.25rem). Popovers, slideover inner cards and alerts use 8px (`rounded-lg`). Bubbles use 12px (`rounded-xl`) so they read as soft objects above the hard-edged View. The View frame keeps a 2px radius. It represents a device viewport, and rounding it further would misrepresent the View's own corners. Pins are Figma-like teardrops: a circle with the bottom-left corner pulled to 2px, whose tip marks the anchor point exactly. Status dots and avatars are circles.

Dashed 1px borders mean "nothing authored yet" or "not placed": empty Variant lists, empty Spec sections, the comment-mode hover outline, a pending (unsent) pin, and the unplaced-comments tray. Solid borders mean real content.

## Components

Every component below is a Nuxt UI 4 component themed through `app.config.ts` and CSS variables. Custom markup exists only for the canvas overlay (pins, bubble anchoring, blueprint labels), where no component fits.

### Buttons
- **Shape:** gently squared (6px radius), 32px tall at desktop (`md`), 28px for dense toolbars (`sm`). On coarse pointers they grow to a 44px minimum target.
- **Default:** `color="neutral" variant="outline"` (white or graphite-900 fill, graphite-450 / graphite-500 boundary). The theme makes this the default, so violet must be asked for.
- **Primary:** `color="primary" variant="solid"`. Iris-600 with white text in light; iris-400 with graphite-900 text in dark. Hover moves one ramp step and never lowers opacity. At most one per region.
- **Ghost icon:** toolbar and row actions, 32px square, graphite-600 icon, `bg-elevated` on hover. Always has a translated `aria-label` and a `UTooltip` with its shortcut (`UKbd`).
- **Focus:** a 2px solid Iris outline at 2px offset on every variant (overriding Nuxt UI's 25%-opacity outline, which fails 3:1).
- **Destructive:** `color="error" variant="soft"` in confirmation surfaces only.

### Chips and badges
- **Status badges:** `UBadge variant="subtle"` at 12px (the theme re-maps `xs`/`sm` to 12px).
  - Review `open` uses annotation, `ready-for-review` info, `resolved` success.
  - Decision `pending` uses warning, `decided` success, `deferred` neutral.
  - Each status badge carries a leading Lucide icon, so color is never the only signal.
- **Mono chip:** neutral `UBadge variant="soft"` with the mono font, for ids, revisions, dimensions and change domains. Long ids truncate in the middle; the full value is in a tooltip, with a copy button where useful.
- **Count:** neutral soft `UBadge` beside nav items and tabs. Annotation-colored only for unresolved comment counts.

### Inputs / Fields
- **Style:** `UInput`, `UTextarea` (autoresize), `USelect` and `USelectMenu`, outline variant on `bg-default` with a graphite-450 / graphite-500 boundary, 6px radius, 13px text (16px on touch).
- **Focus:** the boundary becomes a 2px Iris ring.
- **Error:** fault-red boundary plus `UFormField` error text with an icon. Server diagnostics render as a `UAlert` listing each diagnostic.
- **Revision conflict:** a caution `UAlert` above the form: "This changed since you opened it." with "Reload" and "Review changes". Never auto-retry.

### Navigation
- **Primary navigation:** a vertical `UNavigationMenu` in the sidebar with four items (Overview, Views, UX Flows, Reviews), each with a Lucide icon, label and count.
  - Active: `bg-elevated` with `text-highlighted`, plus a 2px Iris inset bar on the leading edge.
  - Inactive: `text-muted`. Hover: `bg-muted`.
- **Secondary navigation:** a "Workspace" group (Settings, Locales, Assets, Adapters & Catalog) sits below a separator at the sidebar foot.
- **Collapsed rail:** 56px, icons only, with tooltips.
- **Mobile:** bottom `UNavigationMenu`, 56px tall plus the safe area, with icon and label (12px).

### Tree (Widget layers)
- `UTree` with full nesting. Rows are 28px with a 16px indent per depth level, a type icon from Catalog metadata, the Widget label (13px) and a mono id (12px, muted, revealed on hover or selection).
- Trailing indicators: a comment count (annotation) and a diagnostic dot (warning or error).
- Selected: Iris tint fill with iris-700 / iris-300 text. Keyboard: arrows, Home/End, type-ahead, Enter to select, `C` to comment on the focused Widget.

### Canvas tool palette (signature)
A floating, centered pill at the bottom of the canvas: `UFieldGroup` of ghost `UButton`s. The tools are Inspect (`V`), Comment (`C`) and Interact (`I`), followed by a separator, the comment filter (`UDropdownMenu` with open / ready / resolved checkboxes) and the pin visibility toggle (`Shift+C`). The active tool uses an Iris fill. Comment mode instead tints the active button Marker and shows a 2px Marker inset line along the top edge of the canvas, so the mode is unmistakable without a modal.

### Comment pin (signature)
- **Default:** a 28px teardrop in pin fill (marker-600 / marker-400) with the thread starter's initials (12px, 600). An agent-started thread shows a `i-lucide-bot` glyph instead. It carries the Pin shadow and a 2px panel-colored ring.
- **States:**
  - **hover**: lifts 1px and shows a tooltip with author and excerpt;
  - **selected/open**: a 2px Iris outer ring, the bubble attached;
  - **ready-for-review**: a 12px notice-blue badge with `i-lucide-eye` at the top-right;
  - **resolved** (only when filtered in): a 24px graphite-500 teardrop with `i-lucide-check`;
  - **pending**: a dashed outline, the unsent composer still open;
  - **edge**: the Widget is off-screen, so the pin is clamped to the frame edge with a direction chevron;
  - **unplaced**: the anchor is invalid, so the thread is listed in the canvas's bottom-left tray in caution or fault color, never drawn on a guessed spot.
- **Clusters:** three or more pins within 20px merge into a count pin ("+4") that expands on click.

### Composer and thread bubble (signature)
- A `UPopover` whose `reference` is a virtual element at the pin tip. It prefers the right side of the pin and flips to stay inside the canvas.
- 320px wide, 12px radius, Overlay shadow, `bg-default`. The header holds a target chip (Widget type plus mono id) and the Variant scope `USelect` ("This Variant" / "All Variants").
- The body is a `UTextarea`, autoresizing up to 8 lines. The footer holds "Cancel" and a solid "Comment" button (`⌘↵`).
- A thread bubble has the same frame. It shows a compact timeline (messages, re-anchors, submissions, lifecycle events), a reply field, and inline lifecycle actions: "Resolve" (only on `ready-for-review`, naming the accepted submission) and "Reopen". An overflow `UDropdownMenu` holds Copy link, Re-anchor, Promote to Decision, Open in Reviews, and Copy thread ID.
- On touch with the virtual keyboard open, the bubble docks to a bottom `UDrawer` and keeps a target chip that links back to the pin.

### Blueprint selection label (signature)
For the selected Widget, a mono chip sits outside the top-left corner of its outline ("Button · #checkout-submit") and a dimension chip sits below its bottom edge ("320 × 44"). Both are 12px mono on `bg-default` with a 1px hairline, and they float in the Workbench overlay, never inside the iframe. The selection outline is 1.5px solid Iris. The Inspect hover outline is 1px Iris at 60%. The Comment hover outline is 1.5px dashed Marker.

### Cards / Containers
- Prefer panel sections separated by hairlines. `UCard` (variant `outline`, 8px radius, 12px padding, no shadow) is reserved for discrete objects in a collection: evidence captures, Overview readiness rows on mobile, asset tiles.

### Feedback
- `UAlert` (subtle) for persistent inline states: invalid anchor, invalid Variant, adapter set invalid, revision conflict.
- Toasts (`useToast`) only for completed or failed operations, and for the missing-View navigation notice. Never for errors the user must act on in place.
- `USkeleton` for loading lists and panels. `UProgress` for capture and export runs.
- `UEmpty` for empty states, always with one next action.

### Motion
State changes only, 120–240ms, never choreography.

- **Micro** (hover, press, toggles): 120ms with `--ease-out-quiet: cubic-bezier(0.2, 0, 0, 1)`.
- **Reveal** (popover, bubble, tooltip, menu): 160ms. Opacity plus a 4px translate from the anchor side. Exit is 100ms with `--ease-in-quiet: cubic-bezier(0.4, 0, 1, 1)`.
- **Panel** (slideover, drawer, sidebar collapse): 220ms.
- **Pin drop:** 180ms, scaling from 0.6 at the tip origin with no bounce.
- **Zoom by button or shortcut:** a 160ms transform tween. Wheel and pinch zoom are never tweened.
- **Live geometry:** overlay pins follow geometry per animation frame and never animate between positions.
- **`prefers-reduced-motion`:** all transforms are removed, opacity-only reveals last at most 80ms, and zoom is instant.

### Density and focus
Desktop is compact (28px rows, 32px controls). Tablet and mobile are comfortable (44px targets). The density follows `pointer: coarse`, not the viewport width alone, so a touch laptop gets touch targets.

Focus is always a 2px Iris outline at 2px offset, never removed, and never covered by a sticky bar (WCAG 2.4.11). Canvas pins are focusable buttons in reading order (top-to-bottom, then left-to-right). `Tab` cycles pins, `Enter` opens the bubble, and `Escape` closes it and returns focus to the pin.

## Do's and Don'ts

### Do:
- **Do** keep the iframe at its canonical logical viewport size and scale only the outer frame. Pins and labels live in the Workbench overlay, positioned from iframe-reported geometry.
- **Do** use Iris (`iris-600` / `iris-400`) only for selection, focus and the single primary action per region.
- **Do** use Marker magenta only for human annotation: pins, the comment tool, comment counts, `open`.
- **Do** keep every text size at 12px or above, and use 13px for controls and 14px for prose.
- **Do** pair every status color with an icon and a word.
- **Do** keep the chrome theme and locale independent of the Preview render context. The Theme select in the canvas toolbar changes the View; the preferences menu changes the Workbench.
- **Do** keep IDs, revisions and evidence digests one click away (Inspector "Details" disclosure, a tooltip, a copy button), never in the default reading path.
- **Do** show unresolvable anchors in the unplaced tray with their last-known hint, and offer explicit Re-anchor.

### Don't:
- **Don't** hard-code palette classes (`neutral-*`, `slate-*`, `green-*`, `dark:` variants) in components. Use Nuxt UI semantic utilities and `--wb-*` tokens.
- **Don't** use green for anything but success, or violet for anything but you-are-here.
- **Don't** use emoji as icons, gradients, glassmorphism, glows or neon accents.
- **Don't** use Nuxt UI `xs`/`sm` badges at their stock 8px and 10px. The theme re-map exists to prevent it.
- **Don't** lower opacity for hover on filled controls (white on iris-600 at 75% drops below AA).
- **Don't** draw a pin at a guessed position when the anchor is invalid or the mapping is unmeasurable. Hide it, explain it, and offer repair.
- **Don't** put a transparent pointer-capture layer over the iframe for targeting. The iframe hit-tests; the Workbench only draws.
- **Don't** add nested cards, equal-weight tab grids, or a dark-only shell.

The Nuxt UI colors plugin injects `--ui-color-<name>-<step>` from the Tailwind `--color-<name>-*` ramps registered above. Overriding `--ui-primary` and the other `--ui-<color>` variables in `:root` and `.dark` is the documented way to pick the shade per mode. The Workbench chrome color mode comes from `@nuxtjs/color-mode` (system / light / dark in the preferences menu). The Preview iframe's Workspace theme is a separate render-context key and never reads `.dark`.
