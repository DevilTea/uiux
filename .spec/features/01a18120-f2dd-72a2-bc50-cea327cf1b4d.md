---
id: 01a18120-f2dd-72a2-bc50-cea327cf1b4d
title: Requirement references
summary: How Views, Variants and UX Flows record the requirements they
  implement, how a Workspace names its requirement source and marks requirements
  that have no UI, and how coverage is shown in the Workbench and read by
  Agents.
rules:
  - id: 01a18120-f98f-70d6-9b2f-1f0f835efaa7
    statement: A View's Spec, each of its Variants and each UX Flow may list
      requirement references, opaque IDs of requirements that the product's own
      specification states; Clause 01a18120-f403-796d-9ae7-7889fa233bca gives
      their shape.
  - id: 01a18120-fa17-7184-be86-43753e4614af
    statement: "A Variant's references add to its View's: a View counts as
      referencing a requirement when the View or any of its Variants lists it."
  - id: 01a18120-faa6-72e1-8e56-12d44df08b52
    statement: A UX Flow step carries no requirement reference; only the Flow lists them.
  - id: 01a18120-fb3a-7a58-b93e-99b75d658980
    statement: "Without a requirement provider, UIUX checks no ID against any
      source: it stores each reference as written, within Clause
      01a18120-f403-796d-9ae7-7889fa233bca, and reports it as unverified."
  - id: 01a18120-fbc4-7edc-aa2e-f77f94603545
    statement: With a `spec` provider, a reference or `noUi` entry whose ID the
      provider lacks is reported with the diagnostic of Clause
      01a18120-f5b9-75e2-83a6-8048dc5d6fba and kept as written, never dropped or
      rewritten.
  - id: 01a18120-fc4e-7a80-8ba5-68cb1aefb363
    statement: With a `url` provider, the Workbench shows each reference as a link
      built from the provider's template, and the provider supplies no coverage.
  - id: 01a18120-fcd7-721e-ac3f-2839a47d7904
    statement: UIUX reads a `spec` provider's Spec Tool workspace read-only and
      never writes it.
  - id: 01a18120-fd5d-7226-bc8c-5aabd117ce88
    statement: Coverage is the share of the provider's requirements that are not
      marked `noUi` and that at least one View, Variant or UX Flow references.
  - id: 01a18120-fde6-7fae-bc6f-c5ceffe81b12
    statement: A requirement marked `noUi` is outside coverage, whatever references
      it, and its reason stays visible with it.
  - id: 01a18120-fe71-7c8c-a69e-5d74c152cb58
    statement: The Workbench shows the requirement references that a View and a UX
      Flow list on their pages, and on a View's page names the Variant behind
      each reference that only a Variant lists.
  - id: 01a18120-feff-713c-b556-6511fad1a0d5
    statement: With a `spec` provider, Overview has a Requirements tab listing each
      requirement as referenced, unreferenced or `noUi`, the unresolved IDs and
      the coverage, each linked to the Views, Variants and UX Flows that
      reference it.
  - id: 01a18120-ff8e-7eaa-9931-814e92da017b
    statement: An Agent reads the same coverage as the Resource of Clause
      01a18120-f903-7f8d-9b44-d581ab520c0d.
  - id: 01a18121-0018-7013-9c5d-16e1efbb55a0
    statement: A requirement diagnostic never makes a View, a Variant or a UX Flow
      unusable for rendering, capture or playback.
  - id: 01a18121-00a2-7263-a1e6-3729863eb0f6
    statement: A change that alters only requirement references leaves every formal
      capture fresh.

## Notes

- Requirement IDs are opaque to UIUX; for this repository they are the UUIDs of `.spec/` Rules (Discussion #379, P3). The Workspace persisted format Contract owns the shapes, limits and diagnostic codes (01a18120-f403-796d-9ae7-7889fa233bca, 01a18120-f49d-7b42-bad5-69d727f6a33a, 01a18120-f52d-7448-bf25-13e37a8d791c, 01a18120-f5b9-75e2-83a6-8048dc5d6fba), and the MCP interface Contract owns the coverage Resource (01a18120-f903-7f8d-9b44-d581ab520c0d).
- Settled in the `.spec/` PR of #379 where the proposal said "to settle in the .spec PR": the limits and the allowlist of the `spec` provider's path (Clauses 01a18120-f403-796d-9ae7-7889fa233bca, 01a18120-f49d-7b42-bad5-69d727f6a33a, 01a18120-f52d-7448-bf25-13e37a8d791c); the Flow step carrying no reference, which stays the proposal's default; `noUi` living only in the Workspace settings, with no provider hook, the proposal's stated default.
- The Workbench only shows references, the provider and `noUi`; the proposal names MCP as the authoring path, and this Feature specifies no Workbench editor for them.
- A reference-only edit to a Flow is not addressed beyond the Flow's own revision: this Feature makes no claim about Flow trace freshness.
