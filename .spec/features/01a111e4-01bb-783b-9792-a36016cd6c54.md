id: 01a111e4-01bb-783b-9792-a36016cd6c54
title: Review threads and anchors
summary: "Review threads as canonical Workspace resources: what a thread is
  anchored to and its Variant scope, invalid anchors and explicit re-anchoring,
  retention, the Workbench thread timeline, and how threads are summarized,
  listed and filtered."
rules:
  - id: 01a11544-511c-7f6e-8644-f4c86b760704
    statement: A Review thread's identity is independent of the View and Widget it
      concerns, its text and its position in any list, so re-anchoring or
      editing a thread never changes its identity.
  - id: 01a11544-514a-733b-955a-614571facc1c
    statement: A Widget anchor names its target only by stable View and Widget
      identity, never by DOM selector, rendered geometry, child index or tree
      path, so moving the Widget within its View keeps the anchor.
  - id: 01a11544-5170-7aec-8d4b-56b8faacfca2
    statement: A comment about a whole View is anchored to that View's RootShell Widget.
  - id: 01a11544-5194-7c98-adf1-fc0a302a569f
    statement: Feedback about the product as a whole is anchored to the Workspace
      itself and names no View or Widget.
  - id: 01a11544-51b8-76a3-ab62-d87207014806
    statement: Creating a thread always states its anchor; an omitted anchor never
      defaults to the Workspace.
  - id: 01a11544-51dd-73c6-826c-454ff3b23cef
    statement: A Widget thread's Variant scope limits it to the named Variants of
      its View, and an empty scope means every current and future Variant.
  - id: 01a11544-5201-70e6-9e60-a2433deb62b0
    statement: A named Variant in a thread's scope that no longer exists makes that
      part of the anchor invalid, and the thread is kept.
  - id: 01a11544-5228-70b4-96be-e5e032bb3b63
    statement: When a thread's anchored View or Widget no longer exists, the thread
      is kept unchanged with an invalid anchor; deleting the target never
      resolves, moves or deletes it.
  - id: 01a11544-524d-7fd7-aa5e-d3f4388bdd41
    statement: The Workbench shows a thread whose anchor is invalid with a
      missing-target notice that offers explicit repair.
  - id: 01a11544-5275-7aa3-8807-ae9cf39a4b67
    statement: UIUX never binds a thread to another target by DOM selector, tree
      position, geometry or similarity.
  - id: 01a11544-529e-7ace-beeb-c5ce2b2071e8
    statement: A Workspace anchor always resolves, so a Workspace thread never has
      an invalid anchor.
  - id: 01a11544-52c4-7105-895f-d94dc88ec4e9
    statement: Only an explicit re-anchor changes a thread's anchor or Variant scope.
  - id: 01a11544-52e9-7559-b671-44d0bdf68879
    statement: A re-anchor may move a thread from a Widget to the Workspace, from
      the Workspace to a Widget, or within either, including to the anchor it
      already has.
  - id: 01a11544-530d-7048-96d6-ab6c2d0e92ab
    statement: Every re-anchor appends an immutable history event with the previous
      and new anchor and Variant scope, so earlier anchors stay in the thread's
      history.
  - id: 01a11544-5332-7801-9845-3306c8003cb4
    statement: No Workbench or MCP action deletes a Review thread except a
      retraction that the retraction Rules permit, so resolved threads stay
      stored as design history.
  - id: 01a11544-5357-7b50-b864-dbba2fc0b082
    statement: A reply appends a new message to the end of the thread's messages, on
      a thread of any status.
  - id: 01a11544-537b-788e-8713-76f9a9ce705b
    statement: A Review thread's list item summarizes its anchor, Variant scope, pin
      hint, status, current resolution and latest activity, and briefly its
      latest message and current submission.
  - id: 01a11544-53a0-781e-bed5-4420f5fabcc1
    statement: A thread's latest activity is the newest authored time among its
      messages, message edits, submissions and history events.
  - id: 01a11544-53c4-7042-8e81-e381dd1d4450
    statement: Listing and searching Review threads accept structured filters for
      status, View, anchor validity, Variant scope, change or Evidence domain,
      current resolution and anchor scope.
  - id: 01a11544-53e8-75b3-b819-d86993a21069
    statement: The Workbench shows a thread as one chronological timeline of its
      messages, re-anchor events, submissions and lifecycle events, each keeping
      its own type and content, derived from the thread rather than stored.
  - id: 01a11544-540d-765c-8552-d1f3a4d0ef10
    statement: In the Workbench a reviewer can start a Workspace thread from the
      Reviews inbox and from the command palette.
  - id: 01a11e0d-d3f8-7dd4-9994-10ffc065ede1
    statement: Re-anchoring a thread to a Widget from the Workbench keeps the
      thread's recorded render context.

Who may retract a thread is owned by 01a11544-598c-7217-8b56-7cb8ff0236da and 01a11544-5a05-7750-9268-fd666980dd2f. Which tools perform each Review action is owned by 01a11485-f7ee-7102-a12c-694efaeb6d28, which also states that each changes one thread atomically; leases never cover threads (01a11485-efb6-7a68-a726-0f1875b8d015).
- Removing a thread file outside UIUX is an external destructive change (Discussion #7 c2 d8), not a Review action; readers then report the thread as not found.
- The Reviews inbox (default queue order, tabs including Dismissed, facets, deep links such as `/reviews?thread=<id>` and `view=workspace`) belongs to the Workbench information architecture Feature (import batch 7). Handoff treatment of Review threads (Workspace threads in every closure, per-resolution and Workspace-thread counts) belongs to the Handoff Feature (import batch 5).
