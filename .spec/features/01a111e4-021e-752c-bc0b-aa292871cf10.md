title: Preview iframe boundary
summary: "The boundary between the Workbench and the Preview iframe: what the
  iframe owns, how the Workbench observes and controls it, and where Review
  chrome is drawn."
rules:
  - id: 01a1161c-39df-77f1-ba94-302b9da35d39
    statement: For normal control and inspection the Workbench never reads or
      changes the Preview iframe's DOM, Widget Runtime or Blueprint objects,
      even when both share an origin; it uses only the Preview protocol or a
      dedicated channel.
  - id: 01a1161c-3a28-770f-9c62-dd7493437038
    statement: The Preview iframe owns Widget hit testing, Widget identity
      resolution and Widget geometry, and gives the Workbench only canonical
      UIUX identities with structural or geometry data, never raw DOM, Runtime
      or Blueprint objects.
  - id: 01a1161c-3a66-7d06-98ac-a820c6c7b548
    statement: The Workbench draws all Review chrome, including hover and selection
      highlights, comment pins, composers and threads, outside the iframe.
  - id: 01a1161c-3aa0-7bda-8956-3debc38b7a28
    statement: "The Preview protocol is owned by UIUX: reused devtools primitives
      stay behind a UIUX bridge, and UIUX never depends on Widget Lab modules or
      adopts the widget-devtools wire protocol as its own."

## Notes

- Owner ruling 2026-10-07 (batch 6a confirmation): render-context changes (View, Variant, Locale, viewport and theme) reach the mounted Preview document on the dedicated `uiux:preview:context` channel that Discussion #1 c165 decision 2 allows, outside the protocol envelope and its session, generation and acknowledgement gates; it keeps the origin and source checks of 01a1161c-3fe9-7b4b-ac66-efbfcca4eb30, and its post shape is non-normative, with code at 6171f5d authoritative (`app/composables/usePreviewSession.ts#L269-L310`, `app/pages/preview.vue#L444-L470`, `src/preview/protocol/transport.ts#L4-L13`).
- Same-origin hosting is integration isolation, not a security sandbox (Discussion #1 c5): the origin and source checks of 01a1161c-3fe9-7b4b-ac66-efbfcca4eb30 keep stray windows out of the channel but do not defend against Adapter code, which runs in the Preview origin as trusted Workspace code (Discussion #2 c37).
