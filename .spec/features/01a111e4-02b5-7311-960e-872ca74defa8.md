id: 01a111e4-02b5-7311-960e-872ca74defa8
title: LAN reviewer access
summary: "The opt-in LAN listener through which human members on other devices,
  and Agents with LAN-enabled Tokens, reach the same server: its trust model,
  credentials, transport security and plain-HTTP warning."
rules:
  - id: 01a11485-eea0-73cc-9a95-28bde12056ae
    statement: LAN access is an opt-in second listener into the same server and
      application layer; the loopback listener behaves exactly as it does
      without it.
  - id: 01a11485-eeba-7d19-a2bf-d117734bac87
    statement: Listener-specific policy follows the listener that accepted the
      connection, never the client's source address.
  - id: 01a11485-eed5-7766-8a8b-b932f96d03b0
    statement: A LAN request is authenticated like a loopback request, and the
      member's keys decide what it may do; the LAN listener has no route
      allowlist of its own, so a holder of `views.write` may author Views over
      the LAN.
  - id: 01a11485-eef1-76e5-aec0-775c506bf67d
    statement: Member, Token, invite and session administration is never served on
      the LAN listener, so no credential is created or shown over it.
  - id: 01a11485-ef0e-7dd9-990b-457db879c039
    statement: A Token works on the LAN listener, for `/mcp`, `/api/*` or signing
      in, only if it was created with the LAN flag; a default Token is
      loopback-only, so an everyday Token never crosses the LAN.
  - id: 01a11485-ef28-754a-b8bf-a2f97a6563fc
    statement: Without TLS the LAN listener serves plain HTTP; with both TLS flags
      it serves HTTPS.
  - id: 01a11485-ef46-720c-8405-46167fc7cf10
    statement: When the LAN listener serves plain HTTP, UIUX shows a non-dismissible
      warning that anyone on the network can capture sign-in links, session
      cookies and LAN Tokens and reuse them; with TLS no warning is shown.
  - id: 01a114ec-e45e-7a16-a8bf-14093646af13
    statement: The plain-HTTP warning appears next to the LAN URLs at startup, with
      the number of LAN-enabled Tokens, in the output of `uiux token create
      --lan`, and on the sign-in and Members pages on LAN origins.
  - id: 01a11485-ef62-772e-a71e-6657bf209141
    statement: With the LAN listener running, startup prints each reachable LAN URL.
  - id: 01a11485-ef7e-79ee-abc1-92bcdf6b3ce7
    statement: Formal capture keeps loading Preview from the internal loopback
      origin and never uses the LAN listener.
  - id: 01a11485-ef9a-7f3f-87ee-32800ddbbb76
    statement: "The Workbench works on a plain-HTTP LAN origin, which is not a
      secure context: copying text and generating identifiers do not depend on
      secure-context-only browser APIs."
