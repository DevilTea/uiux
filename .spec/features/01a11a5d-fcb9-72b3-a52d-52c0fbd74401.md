---
id: 01a11a5d-fcb9-72b3-a52d-52c0fbd74401
title: Named Checkpoints
summary: "Versions that a human, an Agent or UIUX itself names on purpose:
  creating one, what creating it does, immutability, the system Checkpoints,
  deletion and the Workbench action."
rules:
  - id: 01a11a5e-0919-73d1-9082-cd17a275da0c
    statement: A Checkpoint is a version with a required name and an optional
      plain-text note within the limits that the Version history records
      Contract sets; Checkpoint names need not be unique.
  - id: 01a11a5e-096a-761e-a65a-6fd66e7e0b12
    statement: Creating a Checkpoint snapshots the current versioned files and never
      changes a canonical file.
  - id: 01a11a5e-09bb-755c-9253-3cbff9f65da9
    statement: "A Checkpoint is immutable: it is never renamed, its note is never
      edited and it is never moved; a correction is a new Checkpoint."
  - id: 01a11a5e-0a0c-7d65-8d09-9a71a730ec61
    statement: Creating a Checkpoint needs no edit lease, and humans and Agents may
      both create one.
  - id: 01a11a5e-0a5e-7562-91cd-8c48eac71529
    statement: While the Workspace needs migration or its schema is unsupported,
      creating a Checkpoint through `/api/*` or `/mcp` is refused with the
      schema diagnostic that the Workspace persisted format Contract assigns.
  - id: 01a11a5e-0ac6-79b2-b542-1e527e8b4fdf
    statement: No Checkpoint is created automatically when an Agent's task ends;
      `release_lock` closes only the open autosave.
  - id: 01a11a5e-0b23-7d4f-954a-26fcde4a8014
    statement: The pre-migration system Checkpoint that the Command-line interface
      Contract has `uiux migrate` create is written before any step and is not
      part of one, so a failed migration leaves it in place.
  - id: 01a11a5e-0b79-7920-953b-288cede75df8
    statement: The first server start of a Workspace with no history on that host,
      such as a new git worktree, creates the Baseline system Checkpoint.
  - id: 01a11a5e-0bcd-7462-849b-54f6695056b7
    statement: Checkpoints are never pruned automatically.
  - id: 01a11a5e-0c1f-7b18-83a2-d9cd62b78ae9
    statement: Deleting a Checkpoint removes only its record and leaves its blobs to
      artifact cleanup.
  - id: 01a11a5e-0c71-78d1-9adb-14db6c67ab9c
    statement: The Workbench offers Create Checkpoint, with a name and a note, as a
      toolbar action and a command-palette entry.
  - id: 01a11a5e-0cc5-7548-ab99-8894c2e0dce4
    statement: The Workbench's Create Checkpoint dialog warns when another member
      holds edit leases.
  - id: 01a11e0d-da2f-718f-b3c3-acf2f11fb683
    statement: The Activity timeline offers a Delete row action on each Checkpoint
      and deletes it only after explicit confirmation.
---
