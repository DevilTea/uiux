---
id: 01a111e4-016a-764a-8947-93dbdd331904
title: Checks
summary: "The Workspace Checks surface: which findings it gathers, how it
  reports their origin and check state, how it groups, orders and navigates
  them, and what it leaves out."
rules:
  - id: 01a115cd-bb01-7830-abdc-43cf81dc0897
    statement: Checks lists diagnostic findings only, never Review status, approval
      queues or tasks.
  - id: 01a115cd-bb33-70a8-a09f-999e06ce38ed
    statement: Checks gathers translation reminders, current Preview translation
      warnings, structural and schema validation findings, current Runtime
      errors, Catalog problems of used entries and Product Kit findings.
  - id: 01a115cd-bb64-75c2-a7df-2c8dd338453d
    statement: Each finding keeps its origin, scope, check state and severity;
      Checks never merges sources into one warning type.
  - id: 01a115cd-bb96-7131-99d9-a3882829590c
    statement: Checks tells apart not yet checked, checking, completed with or
      without findings, and failed or incomplete, and never shows an unrun check
      as zero findings.
  - id: 01a115cd-bbc7-7f77-bc7c-c88a97367b0e
    statement: Opening Checks never runs validation, forces hidden Properties to
      evaluate or invokes `t`.
  - id: 01a115cd-bbfa-7022-b8f1-ef8734cbe45e
    statement: Run Checks explicitly produces or refreshes a complete check result,
      and live background warnings are never presented as a complete run.
  - id: 01a115cd-bc2c-795f-babe-0d19eb80de96
    statement: Each Run Checks produces a new immutable Evidence record of its
      result instead of overwriting an earlier one.
  - id: 01a115cd-bc5e-710e-bbe2-a3d5f51469fb
    statement: Checks never shows a Runtime error from an earlier Preview, Variant
      or Locale as a current finding.
  - id: 01a115cd-bca6-7c80-b393-5b9260c2ce18
    statement: Listing a blocking structural or executable problem in Checks never
      weakens its Preview, capture or Review gating.
  - id: 01a115cd-bcde-797b-b9f4-dc60d7d853bd
    statement: Historical Review and capture Evidence never merges into the live
      Checks list.
  - id: 01a115cd-bd13-778b-8a0a-b4d43cd98aa7
    statement: Checks groups and filters findings by source, category, severity,
      View and Variant.
  - id: 01a115cd-bd48-7c10-82fc-827d5e8e5ba8
    statement: By default Checks orders findings by severity, then code or category,
      then stable View and Widget location.
  - id: 01a115cd-bd7d-705f-be59-b24cc4bd389e
    statement: "Selecting a finding opens its exact authoring context: the View,
      Variant, Widget, file or editor it concerns."
  - id: 01a115cd-bdb2-7de2-abb9-54f592539471
    statement: Translation reminders appear in Checks by Locale, key and reminder
      type and open the matching translation-table cell.
  - id: 01a115cd-bde8-736b-9153-7baaedf24f98
    statement: Checks groups translation warnings primarily by warning code, then by
      key and missing parameter, each group counting and listing its affected
      Widget and Property occurrences.
  - id: 01a115cd-be1d-74aa-8639-23f43671e86d
    statement: Within a translation-warning group, occurrences are ordered by View,
      Variant, Widget, and Property or Catalog field.
  - id: 01a115cd-be51-740b-8472-c08dc7138e3e
    statement: Checks reports Catalog problems only for entries that at least one
      View uses; problems of unused entries appear only in Catalog management.
  - id: 01a115cd-be84-755b-b9fb-62f519cf989c
    statement: One Catalog problem shows once, expanding to each distinct affected
      View and then each distinct affected Widget, with separate counts at each
      level.
  - id: 01a115cd-beb7-7024-9e44-0b5fe9ecf9af
    statement: The affected Views and Widgets of a Catalog problem follow current
      Workspace usage without revalidating the Catalog.
  - id: 01a11bb1-a75d-7138-a5b9-8618c9c6c78c
    statement: The repeat-capture check captures the same render context twice and
      reports a finding when the two screenshots differ in any byte.
  - id: 01a11bb1-a7bf-74ae-9639-b39f246fa117
    statement: The live-versus-fresh check compares a live Preview of a Variant with
      a fresh Runtime of that Variant through a capture-harness hook, and
      reports a finding when they differ.
  - id: 01a11bb1-a827-75e3-b05f-4099146cff2a
    statement: Checks reports each registry component that declares neither its
      props nor its emits.
  - id: 01a11bb1-a88c-7d78-8633-1c3b55588910
    statement: "Product Kit findings are non-blocking: they never block Preview,
      capture, authoring or the Handoff readiness claim."
  - id: 01a175ed-ec07-7f92-8e9b-6c26aad6ee38
    statement: "Checks derives each finding's severity from its source in the
      Workbench, with no severity on the wire: resource-read diagnostics,
      Catalog problems, the missing default Locale and current Runtime errors
      are errors; translation reminders, Preview translation warnings and
      Product Kit findings are warnings."
  - id: 01a175ee-07de-71d9-9443-898f3befc30a
    statement: Checks attributes a View diagnostic whose path begins with
      /variants/<name> to that Variant, so the Variant filter lists it; the name
      is read with its JSON Pointer escapes undone.
  - id: 01a17671-6251-75dc-a810-088743e727d0
    statement: "A recorded Run Checks result is Evidence of what the Workbench
      reported, never a formal capture: capture listing, staleness and Handoff
      ignore it."
  - id: 01a178c4-7cdb-7072-9621-ed215ad45a97
    statement: The Preview's translation source is failed when the Preview could not
      load or is blocked, completed only when its report's coverage is complete,
      and otherwise incomplete, as is a report that was cut.

## Notes

- Implementation note (as of c14853b, not a requirement): Run Checks runs the Product Kit Checks on the server (`POST /api/product-kit/checks`, a Workbench session with `evidence.capture`, since the run starts a capture browser, by [ruling 1 of the #139 owner rulings on PR #212](https://github.com/DevilTea/uiux/discussions/139#discussioncomment-18945630); the props and emits check also needs `product-kit.source.read`, and without it that check is incomplete). The capture checks cover each View's base state and each Variant at the Workspace's default locale, viewport and theme, at most 12 render contexts per run, one run at a time. Each page load runs under the formal capture timeouts and each in-page step (the font and image waits, the live State write, the markup snapshot) under the same step timeout; no render context starts after the 120 s run deadline, at which the browser is closed and whatever is in flight is abandoned. A context left out by any bound makes its check incomplete, never clean. The live Preview of a Variant (01a11bb1-a7bf-74ae-9639-b39f246fa117) is the base state's Runtime with the Variant's State written in place, since selecting a Variant builds a fresh Runtime, which remounts every component. A capture difference is attributed to the Widgets whose own markup differs and, through the Product Kit `widgets` table, to a registry component. The check states use non-normative `checks.*` codes, with code authoritative.
