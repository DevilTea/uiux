---
id: 01a19b99-c9ee-7dcb-ae96-bbe31f12591c
title: View thumbnails
summary: "Display-only preview images of Views: what a thumbnail is, where it is
  kept, how the server captures and refreshes it after a quiet period, what a
  failed capture leaves behind, and how a thumbnail is read, requested and
  announced."
rules:
  - id: 01a19b99-cfcc-7abb-8be5-75c2cc6e7148
    statement: A View has at most one thumbnail, a display-only image of its base
      render in the default context that `uiux evidence capture --view` selects
      (Clause 01a19a17-1381-74db-bda9-efd8176865c6).
  - id: 01a19b99-d05d-7c24-9ec7-899038e134b6
    statement: A thumbnail is kept only in the host-local cache of Clause
      01a19b99-cbd0-7076-b286-a6cee12af0f3, never in the Workspace, the artifact
      store, version history or Git.
  - id: 01a19b99-d0f0-7233-b0c1-7569a51379ee
    statement: "A thumbnail is not Evidence: readiness, Handoff, Evidence freshness
      and artifact garbage collection never count it, and no Review, Spec or
      Decision cites it."
  - id: 01a19b99-d186-7fa7-abe3-1570a67772a8
    statement: The server captures a thumbnail from the clean Preview Host with the
      engine of the shared capture service (Rule
      01a115cd-c395-72b0-be67-4a77c4d2ade4).
  - id: 01a19b99-d221-715d-979a-1977a210a7b2
    statement: A View's thumbnail is missing when it has no file, fresh when a file
      is for its current thumbnail input digest (Clause
      01a19b99-ccfa-74bb-9671-08ab5d4e2656), and otherwise stale, also when that
      digest cannot be computed (Clause 01a19b99-cd8b-7a8d-a357-5a55fa9453d7).
  - id: 01a19b99-d2cb-79ae-9e3d-ba6c24bc1f6a
    statement: "The server keeps one quiet period for the whole Workspace (Clause
      01a19b99-ce21-7b2c-b039-f9afa8f95a97): every write to a View, Locale,
      Asset, the Product Kit or the Workspace settings, and every kit build
      output change, restarts it, and a capture pass starts when it has passed."
  - id: 01a19b99-d383-7c4f-ad37-402eca1ef90e
    statement: When the quiet period ends, the server queues each View whose
      thumbnail is then missing or stale.
  - id: 01a19b99-d42e-7b72-b30b-480057b269d9
    statement: A request for the thumbnails of named Views queues those that are
      missing or stale at once, without waiting for a quiet period.
  - id: 01a19b99-d509-708b-8d53-ac59f3ea0413
    statement: Thumbnail captures run within the in-flight limit of Clause
      01a19b99-ce21-7b2c-b039-f9afa8f95a97, and a View already queued is not
      queued again.
  - id: 01a19b99-d5e3-7c51-a1f5-2ea86f20f9f6
    statement: While the kit build is running or has failed, or the default Locale
      has no Locale file, no thumbnail is captured and queued Views stay queued,
      until the next kit build output or the default Locale file appears.
  - id: 01a19b99-d6a9-7208-912e-f154133e553b
    statement: A thumbnail capture that fails, including one of a default context
      that cannot render, or cannot start because the thumbnail input digest
      cannot be computed, changes no stored thumbnail.
  - id: 01a19b99-d760-7e54-9a5e-1d98e9306de7
    statement: A request does not queue a View whose last thumbnail capture failed
      within the interval of Clause 01a19b99-ce21-7b2c-b039-f9afa8f95a97.
  - id: 01a19b99-d814-7fdf-8742-5f7fad22684a
    statement: A View's thumbnail is deleted once the View no longer exists, and a
      View removed while it is queued is dropped from the queue.
  - id: 01a19b99-d8d5-742c-97aa-1b8701b909f7
    statement: Reading a View's thumbnail returns its fresh image, else its stale
      image, and returns no image while it is missing; it never captures one.
  - id: 01a19b99-d985-7c77-9420-1c5a19db7c69
    statement: Listing thumbnails returns, for each named View, its state and
      whether it is refreshing (Clause 01a19b99-cd8b-7a8d-a357-5a55fa9453d7).
  - id: 01a19b99-da51-7960-9a2a-9e26a9324cbc
    statement: When a View's stored thumbnail or its refreshing state changes, the
      server sends the change event of Clause
      01a19b99-cf3c-7a6b-8a2b-492c36c22cc7.
  - id: 01a19bac-ea4d-79eb-9c1b-0c887270b5d5
    statement: Continued writes never delay a capture pass beyond the ceiling of
      Clause 01a19b99-ce21-7b2c-b039-f9afa8f95a97, counted from the first change
      that no pass has yet covered.
  - id: 01a19bb9-95ef-7a61-b7e7-0114c9327cff
    statement: A thumbnail is stored by writing it under a temporary name, renaming
      it into place, then deleting the View's files for other digests, so that
      at most one file per View remains.
  - id: 01a19bb9-9685-7bbf-ab29-a22032c91c64
    statement: A browser never reuses a stored copy of a thumbnail read (Clause
      01a19bb9-8e8a-7775-b19b-76e0b855095c), so a member who loses
      `workspace.read` sees no thumbnail from a cache.

## Notes

- Why a separate Feature: a thumbnail is a server-side, host-local, display-only image with its own cache, queue and failure behavior. The Views tab that shows it is Feature 01a19b99-ca97-7aa7-b326-345c8a26caf3 (Views list layouts); the exact values are Contract 01a19b99-cb2f-76fb-add5-2ede8d0aebdd (View thumbnail records).
- Decision 2 also says the captures share one Chromium. That is a constraint of the worker with no observable behavior, so no Rule or Clause states it; the design records it (launched when the queue is not empty, closed when it is empty).
- There is no HTTP Contract (owner ruling Q4): the read, the listing and the request are described by behavior, and their routes are authoritative in code once built. The key they need is Clause 01a19bb9-8f1f-7482-b6fd-f131a284178e, placed in the Access control Contract beside Clause 01a11bb1-b3c2-7937-96fb-e139c5e566f5 (the Product Kit's read key) so that Rule 01a11485-eaac-7523-998b-26123d7618df holds; Clause 01a11485-fa00-72da-bc46-98302a3c106e is left unchanged.
- The thumbnail never enters Evidence provenance, a version record, a Checkpoint, the Handoff manifest or the artifact store. `uiux access copy` copies the roster and host history only, so a copied Workspace captures its own thumbnails.
- Open questions of the Discussion, settled by the owner answers of 2026-11-02 (https://github.com/DevilTea/uiux/discussions/480#discussioncomment-19347706): a 60 s ceiling on the quiet period (Rule 01a19bac-ea4d-79eb-9c1b-0c887270b5d5), one Workspace-wide timer (Rule 01a19b99-d2cb-79ae-9e3d-ba6c24bc1f6a) and, for a View whose default context cannot render, the placeholder or the previous stale image with no error on the card (Rule 01a19b99-d6a9-7208-912e-f154133e553b and, for the card, Rule 01a19bac-eaeb-777f-b498-2e1c75ec706b of Feature 01a19b99-ca97-7aa7-b326-345c8a26caf3).
- `<wsid>` is derived from the Workspace root's real path (Clause 01a11485-f874-73b4-8b0f-2295c21e9085), so a moved or deleted Workspace leaves an orphan cache under `$UIUX_HOME`, as it leaves an orphan roster and host history; nothing collects it, and deleting it loses only pixels.
