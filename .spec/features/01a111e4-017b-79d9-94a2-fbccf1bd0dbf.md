  and reads artifacts, and when they may be removed."
rules:
  - id: 01a115cd-c16d-7dc8-a770-b6455ab80409
    statement: Derived artifacts are created only by producer actions such as
      capture, checks, Evidence, Handoff export and Checkpoint creation; no Tool
      or route offers a generic artifact write or overwrite.
  - id: 01a115cd-c1a0-72bb-a4f9-1f5063b5d33e
    statement: Artifacts are read by their content identity, never through a path or
      a mutable latest name.
  - id: 01a115cd-c1d4-73fe-b093-c9d1c2226916
    statement: Normal capture, check and mutation actions never delete artifacts.
  - id: 01a115cd-c208-7a92-9582-69966f36e7fe
    statement: Artifact cleanup is an explicit mark-and-sweep that runs only through
      the command of Clause 01a14e30-30de-70c3-888f-63e8982353d7 and removes
      only blobs that no root of Rule 01a14e30-31c0-7289-a944-74af9556eabf
      reaches.
  - id: 01a14e30-31c0-7289-a944-74af9556eabf
    statement: Artifact cleanup's roots are the Evidence that a Review submission
      references, the blobs that a Checkpoint references and, for each View and
      render context, the latest Evidence record; Handoff blobs are not roots.
  - id: 01a115cd-c23e-7143-bd1e-7ffd9fcaa6f2
    statement: Artifact cleanup never rewrites a canonical record.

## Notes

- The store path, identity, immutability and deduplication, and Evidence records as artifacts, are owned by 01a1144e-5508-7eda-a9a0-23fb0d3ebabd, 01a1144e-551f-7352-8973-3d3debe31ee7, 01a1144e-5537-7dbd-8b9e-db2e0634aace and 01a115cd-ce92-7986-b9a6-0e5fa9e092f5; reading an artifact over MCP by 01a11485-f70a-7d29-9b48-e7df3e634a54. Copies inside exported bundles survive Review retraction (01a11544-5acc-7e09-9b85-aca405d1d364).
- Discussion #241 R3 (accepted 2026-10-18) defines the roots (01a14e30-31c0-7289-a944-74af9556eabf) because Evidence records are themselves store blobs and no canonical record names a View's current Evidence: a sweep from canonical records alone would delete fresh Evidence, so the latest Evidence record of each View and render context is a root. Handoff blobs are not roots; a bundle copied out of the store keeps its own copies (01a11544-5acc-7e09-9b85-aca405d1d364). The command is 01a14e30-30de-70c3-888f-63e8982353d7.
- Implementation note (as of 4fc05a7, not a requirement): an Evidence record carries no capture time, so the cleanup takes the latest record of a View and render context to be the one whose store blob has the newest modification time, among the records of one Evidence kind and execution context, keeping every record that ties. The store moves a blob's modification time to now when a producer yields bytes it already holds, so a repeated, byte-identical capture counts as the latest. Modification times do not survive a plain copy or a Git checkout, so the cleanup also keeps every Evidence record whose provenance names the current revision of its View: it keeps more than the roots, never less. A Review thread, a Checkpoint or a stored blob that the cleanup cannot read (not valid JSON, not a valid record, or bytes that do not match the identity) could name any blob, so the whole run is refused before anything is deleted. Only regular files at `artifacts/sha256/<2>/<64>` under their own shard are candidates.
