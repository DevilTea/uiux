id: 01a111e4-0315-7755-b867-e3c7b50d22e6
title: Live refresh
summary: The server pushes content-free change notifications over a server-sent
  events stream so Workbenches re-read what changed; nothing is replayed, a
  reconnect or server restart resynchronizes from canonical resources, and
  polling is the fallback. When a resource changes under a user, the Workbench
  keeps their draft and never resends or retries a write by itself.
rules:
  - id: 01a11485-f34a-7c7e-a69c-fba14914d62d
    statement: The server pushes change notifications to Workbenches over a
      server-sent events stream, `GET /api/events`, open to every authenticated
      member on both listeners.
  - id: 01a11485-f365-70ce-82d9-43ea3f5ea5bb
    statement: On connect the stream sends `hello` with the server instance ID.
      After each successful commit it sends `resource.changed` (kind, key,
      revision) or `resource.removed` (kind, key) for Views, UX Flows, locales,
      Review threads, Assets and the Workspace; it sends `lock.changed` (kind,
      key) when a lease is acquired, released or force-released, and
      `access.changed` when the roster or the member's role changes; a heartbeat
      comment about every 20 seconds keeps it open.
  - id: 01a11485-f382-7307-b0c1-a1947715cf03
    statement: Events never carry canonical content, actors or message bodies;
      clients re-read what changed through the normal point-read and list APIs.
  - id: 01a11485-f39f-7464-9f8f-608335ed9800
    statement: "Nothing is replayed: `Last-Event-ID` is ignored, and a reconnect, or
      a changed server instance ID after a restart, makes the client
      resynchronize what it shows from canonical resources."
  - id: 01a11485-f3bb-760b-9132-0e8c2f6bbf43
    statement: Commits made through `/api/*` and `/mcp` emit alike, because both run
      in the same server process; edits made to Workspace files outside UIUX are
      not detected.
  - id: 01a11485-f3d9-7663-b344-a60c2a949e5e
    statement: When the event stream cannot connect, the Workbench falls back to polling.
  - id: 01a11485-f3f6-72df-b43a-91905eb4970c
    statement: The server caps the open event streams per session, and ending a
      session closes its open stream.
  - id: 01a11485-f414-7882-b94f-cd4236c26d89
    statement: When an on-screen resource changes elsewhere and the user has no
      draft of it, the Workbench re-reads and re-renders it without asking and
      briefly highlights new timeline entries.
  - id: 01a11485-f434-75ed-ab0a-e321468c8407
    statement: When it changes while the user is drafting, the Workbench keeps the
      draft, re-reads and shows an "updated by others" notice above the
      composer; the draft's `expectedRevision` moves to the fresh revision only
      when the user acknowledges the notice.
  - id: 01a11485-f451-72eb-81ad-686aeec7b3eb
    statement: "After a revision conflict the Workbench never resends or retries a
      write by itself: it re-reads, keeps the user's draft or choices, shows the
      new state, and the user acts again against it, so an action aimed at one
      state never silently applies to a newer one."
