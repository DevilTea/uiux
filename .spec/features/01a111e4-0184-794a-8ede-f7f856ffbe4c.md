title: Render context
summary: "Render contexts: Workspace-owned viewport and theme registries,
  Adapter theme validation, and live context switching in Preview."
rules:
  - id: 01a115cd-c27d-78ba-b95d-bf1aa50adec7
    statement: A theme that the active Adapters do not support is reported as a
      render-context diagnostic and never replaced by another theme.
  - id: 01a11a5a-5464-7797-82d3-f8ece37457e5
    statement: UIUX evaluates each active Adapter's theme support on the server,
      once per Adapter resolution, for every theme in the Workspace registry.
  - id: 01a11add-f46d-7e92-8f5a-9d10dba6473d
    statement: Settings, live Preview, formal capture and Product Kit Checks all use
      the theme-support result of the current Adapter resolution.
  - id: 01a11a5a-54e2-7216-a5a1-0de226971850
    statement: An Adapter that declares no theme support supports every theme.
  - id: 01a11a5a-555f-7b4c-8fcc-311c31a99b7a
    statement: A theme-support predicate that throws or returns a non-boolean is an
      Adapter diagnostic, and the theme it was asked about counts as
      unsupported.
  - id: 01a11a5a-55ee-737a-9970-cb9228a2de30
    statement: A theme is unsupported as soon as any active Adapter rejects it,
      whether or not a View uses that Adapter.
  - id: 01a11a5a-566b-70b1-b000-2918519c0d19
    statement: Live Preview shows the render-context diagnostic instead of rendering
      a context whose theme is unsupported, and formal capture refuses that
      context.
  - id: 01a11a5a-56e8-71c8-905a-62ed0476fd8f
    statement: An unsupported theme leaves the Adapter set valid, and contexts with
      supported themes keep rendering.
  - id: 01a11a5a-5769-721b-ad33-d068c7edeb41
    statement: The Product Kit page lists, for each Adapter, the Workspace themes it
      does not support.
  - id: 01a115cd-c2c0-7ec4-9fc8-a491f73f798a
    statement: Execution uses only theme and viewport IDs that exist in the
      Workspace registries.
  - id: 01a115cd-c2f7-7246-9446-e2325b631b5b
    statement: The Workbench may offer convenience viewport presets when one is
      created, but only presets saved in the Workspace are canonical.
  - id: 01a115cd-c32d-7594-8277-c17646f9a500
    statement: In live Preview, changing the Locale, viewport or theme keeps
      unrelated interaction state, such as entered values or expanded controls,
      while the Runtime stays valid.

## Notes

- Who selects the render context and RootShell's read-only exposure are owned by 01a1144e-5174-7ea2-ab72-b5364dd48a03; fresh Runtimes on a Variant switch by 01a1144e-520f-7456-9b7a-eb6b97fc0f75; the registries and their identity by 01a1144e-53aa-7eed-a3bb-e937ff066f7e and 01a1144e-53c4-752f-9c46-c4c70b384165; the impact acknowledgement for renaming a viewport or theme key by 01a1144e-50dd-7b92-aa5e-e175e34bf424; the resolved context shape by 01a115cd-cf3f-7b99-a9a1-4e9ed1011ba1; the RootShell State members by 01a115cd-d372-7777-b286-8f9266a04828.
- Owner ruling 2026-10-07 (batch 5 confirmation): the `render_context.*` diagnostic codes are non-normative; code at 85055c1 is authoritative (`src/domain/render-context/schema.ts`). The same status covers every `render_context.*` code the code emits, as of 547ff0f: `render_context.empty_selection`, `render_context.invalid_locale`, `render_context.unknown_locale`, `render_context.unknown_viewport`, `render_context.unknown_theme`, `render_context.unknown_variant`, `render_context.view_mismatch`, `render_context.viewport_snapshot_mismatch` and `render_context.incompatible_theme`, the last being "the render-context diagnostic" of 01a115cd-c27d-78ba-b95d-bf1aa50adec7 (added by issue #99, so absent from the 85055c1 listing); like the `adapter.*` codes (owner ruling 2026-10-07), none is named in a Clause; owner ruling 2 of https://github.com/DevilTea/uiux/discussions/241#discussioncomment-19162185 (issue #283) confirms `render_context.incompatible_theme` as non-normative with code authoritative, which Product Kit Checks also report.
- Discussion #130 decision 8 (accepted 2026-10-08) specifies 01a115cd-c27d-78ba-b95d-bf1aa50adec7 through the `themeSupport` predicate of 01a11a5a-448c-76ba-94d4-6766435b9e2b. An Adapter accepts Workspace theme IDs through its own configuration (for example a theme map in its own schema), because those IDs are Workspace-local; the Workspace schema gains no Adapter-specific theme field (01a115cd-adb0-750e-a1f9-a254eb3fb25e). Theme support changes only when Adapter code or configuration changes, which Adapter provenance already covers, so Evidence needs nothing new.
- Owner attention 4 of Discussion #130: theme support is set-level, while the user-facing string read "This theme does not apply to this View."; as of 547ff0f (issue #99) it reads "The active Adapters don’t support this theme." (zh-TW 「啟用中的 Adapter 不支援這個主題。」).
- Implementation notes for issue #99 (as of 547ff0f; implementation choices, not Rules): a predicate failure is the non-normative `adapter.theme_support_failed`, reported with the resolution's theme support rather than as a set diagnostic, so it leaves the set valid; a malformed member is `adapter.invalid_theme_support`. A pinned kit build output generation keys its resolution on the Adapter list and the registry's theme IDs, so a registry change is evaluated anew. On a live switch to an unsupported theme the Preview disposes the construction rather than hiding it, and a later supported theme constructs anew, since the Runtime is no longer valid (01a115cd-c32d-7594-8277-c17646f9a500). Handoff export asks no predicate of its own: under `uiux dev` it takes the Preview's resolution of the Product Kit file's Adapter list (01a167bf-1f93-78b7-9045-6562c20f5a42), whose theme support it does not use, and resolves any other list without theme IDs (as of 69b72ed); this Feature names Settings, live Preview, formal capture and Product Kit Checks only. Product Kit Checks render at the default theme; by owner ruling 1 of https://github.com/DevilTea/uiux/discussions/241#discussioncomment-19162185 (issue #283) a render context at an unsupported theme is reported not checked with the non-normative `render_context.incompatible_theme` (a diagnostic of the capture checks' summaries, not a finding), never rendered through the Preview's refusal.
