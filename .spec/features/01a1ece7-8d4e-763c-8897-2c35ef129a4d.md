title: Changes since Git base
summary: "The Workbench's read-only view of what changed in a Workspace since a
  Git base: what it compares, the default base and its toggle, what it reads
  through, what it stores, and when it is unavailable."
rules:
  - id: 01a1ece7-8e23-77a8-9f34-b9c479043ca8
    statement: The Workbench offers a view that lists each canonical resource of the
      Workspace that is added, changed or removed since a Git base.
  - id: 01a1ece7-8f2f-7565-a11f-6d5ac9b5bab3
    statement: Selecting a listed resource shows what changed in it as semantic
      differences between its content at the base and its current content.
  - id: 01a1ece7-8fe1-7d17-8ef4-c706259e5331
    statement: By default the base is `HEAD` and the current content is the working
      tree, so uncommitted changes are listed.
  - id: 01a1ece7-907a-74bb-9602-d9edcce38e42
    statement: A toggle changes the base to the merge base of `HEAD` and the
      repository's default branch, while the current content stays the working
      tree.
  - id: 01a1ece7-910f-7bb4-aebe-ec9cff221ffc
    statement: "The view reads the base content through the `git` CLI and stores
      nothing: no file in the Workspace, no artifact and no host-local cache."
  - id: 01a1ece7-91a3-709c-830d-42ff0393217a
    statement: "The view changes nothing: it offers no action that writes, restores
      or reverts a resource."
  - id: 01a1ece7-9239-7a3f-931f-cbe92f83561f
    statement: When no default branch can be determined, the toggle is unavailable
      and the view keeps `HEAD` as its base.
  - id: 01a1ece7-92cf-79d6-b7d0-1d907da0045b
    statement: When `git` cannot supply the base, the view says so and lists
      nothing, and the rest of the Workbench keeps working.

## Notes

- Why a Feature of its own: the Story 01a111e4-036a-792f-aea9-a9d028bfdb60 needs a way to see what an Agent changed, which the retired version timeline and comparison gave; Discussion #491 P1 gives it this read-only view of Git's state instead. The Rules stay at the level that does not depend on the Workbench layout.
- Where the view appears is Rules 01a11a5e-1946-7217-aff5-db13df3a2977 (Overview's Activity tab, for the whole Workspace) and 01a11a5e-1aa5-7d13-939a-8d99245f7906 (a View's history panel, for that View); the Discussion names no place, so the places of the retired timeline are kept. There is no MCP or HTTP surface (Discussion #491 adds none).
- "Canonical resource" is the term of Rule 01a1144e-4f4b-7ef3-b52e-4dfe9187adfe and the Domain mutations Feature: Views, UX Flows, Review threads, Locales, authored Assets, Workspace settings and the Product Kit file. The view reuses the semantic diff renderers of the retired comparison (`src/domain/history/diff/*`, `ResourceDiff.vue`) with Git as their source; that is an implementation choice recorded in issue #492, not a Rule.
- The canvas before/after comparison of the retired Version comparison Feature needed a version frame and has no replacement.
- Open for the implementation: a repository whose `HEAD` names no commit gives `git` no base. Rule 01a1ece7-92cf-79d6-b7d0-1d907da0045b covers it as a base that cannot be supplied; listing every resource as added would be a refinement the owner can ask for.
