---
id: 01a111e4-0207-7859-a8e0-65bc2fc82289
title: Prototype playback
summary: "The Workbench Prototype player: playing a UX Flow from its entry step
  with a fresh View Runtime per step entry, following reported Widget Events or
  Workbench-driven advances, and what playback never observes or keeps."
rules:
  - id: 01a115cd-327f-7aa6-940d-3ef6749c4efc
    statement: The Prototype player starts at the Flow's entry step.
  - id: 01a11544-63dd-7692-af37-66948504284d
    statement: The Prototype player follows the same canonical Flow the editor
      edits; UIUX keeps no second prototype model.
  - id: 01a11544-6409-7570-9bc7-1f74097739e8
    statement: Every step entry, including a return to the same step, a self-loop or
      a restart, creates a fresh View Runtime from the View IR, plugin defaults
      and the step's Variant, and leaving the step disposes it.
  - id: 01a11544-6434-779d-8de4-8130392ca913
    statement: Interactive state may change within a step but never carries across a
      step boundary.
  - id: 01a11544-645e-7f54-8f63-cbcd63bf1e07
    statement: The Workbench player resolves each reported Widget Event against the Flow.
  - id: 01a115cd-3303-7e54-adb4-1ecd039128e7
    statement: The Preview never receives the Flow and never reports a step.
  - id: 01a11544-6487-7c92-8900-3487708b2def
    statement: Widget Events are observed only while a player has armed the Preview,
      so nothing is observed on the ordinary View canvas.
  - id: 01a115cd-335d-724b-9bd5-df614aa91b72
    statement: An armed Preview observes only the current step's outgoing triggers,
      never Widget Events that no transition references.
  - id: 01a11544-64b1-765f-b42b-58c94785768e
    statement: Each step entry accepts at most one transition from any source; a
      later occurrence, double click or racing advance for that entry is
      discarded.
  - id: 01a11544-64db-7013-981d-a5cae3d71e5e
    statement: The player learns only which armed Widget Event occurred, never its
      arguments or the input that caused it.
  - id: 01a11544-6505-7956-a9db-c5960fc04027
    statement: "Playback history stays in the browser: it is never written to the
      Workspace, sent to the server, or included in Review, Evidence or
      Handoff."
  - id: 01a11544-652f-7816-b08a-05c78c14797c
    statement: The player always offers a labelled, keyboard-reachable Next control
      for each outgoing transition, even when the Preview reports Widget Events.
  - id: 01a11544-6559-753f-a9f8-dc8640332cb1
    statement: "A Workbench-driven advance is a player action, not a Widget Event:
      it invokes no Widget Method, synthesizes no input and is never formal
      Evidence."
  - id: 01a11544-6585-7110-acc9-c3109c329f84
    statement: "Commenting during playback is allowed: in comment mode Widget Events
      cannot advance the player, and Events from that time are never replayed
      afterwards."
  - id: 01a11544-65b9-7614-b4e7-9c18c0613315
    statement: Authoring a Flow keeps no log of Widget Events.
  - id: 01a11544-65f1-7a41-b331-53e818c4ee7d
    statement: When the Preview cannot report Widget Events, the player works
      through its Next controls alone and says so.
