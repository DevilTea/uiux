---
id: 01a111e4-02c1-7229-b7e9-26110ee81a23
title: Agent edit leases
summary: An agent's write to a View, UX Flow, locale, Asset or the Workspace
  settings takes a renewable five-minute per-resource lease (also via
  `acquire_lock` / `release_lock`); other writers are refused with
  `resource.locked`, leases complement but never replace `expectedRevision`,
  Review threads are never leased, and an Owner can force-release.
rules:
  - id: 01a11485-efb6-7a68-a726-0f1875b8d015
    statement: Edit leases cover Views, UX Flows, locales, authored Assets and the
      Workspace settings, one lease per resource; Review threads are never
      leased.
  - id: 01a11485-efd1-7961-9940-785dfc0343d1
    statement: "A lease is held by a member and lives only in server memory. Leases
      are fail-fast: a writer never waits or queues for one."
  - id: 01a11485-efeb-72ce-9e6e-95695ce93405
    statement: A lease expires five minutes after its holder's last successful write
      to that resource or explicit acquire; the duration is fixed and cannot be
      set per call.
  - id: 01a11485-f005-7f10-baf7-58cb17e5d0e1
    statement: A mutation by any principal that would write a resource leased by
      another member is refused before the domain write, with no side effects.
      This includes promoting a Review to a Decision, which writes the View.
  - id: 01a11485-f020-74e0-b721-b4d6a5d15195
    statement: A successful write by an agent member to an unleased resource, a
      create included, takes its lease; a human's writes only check leases and
      never take one.
  - id: 01a11485-f03b-720c-8c70-adcb13c1e05e
    statement: Every successful write by the holder renews its lease on that
      resource, and so does acquiring it again.
  - id: 01a11485-f058-7090-a644-51ac8d3afae3
    statement: The lease check and a tentative reservation happen before the write,
      and a write that fails (for example on a conflict, invalid input or a
      blocked precondition) never leaves a new lease behind.
  - id: 01a11485-f074-7d3c-80f4-f4ced35ef8f2
    statement: A lease ends when its holder releases it, when it expires, when an
      Owner force-releases it, when its holder is removed or loses the Editor
      role, or when the server restarts.
  - id: 01a11485-f08f-794c-a12e-e4ef11b60240
    statement: "An Owner is not exempt from another member's lease: writing the
      resource needs an explicit, visible force-release first."
  - id: 01a11485-f0aa-7377-9d2c-fb24b8231a1c
    statement: "A lease coordinates and never replaces revision checks: the holder
      still sends `expectedRevision`, a lease never turns a conflict into
      success, and writes made outside UIUX ignore leases but are still caught
      by revision checks."
  - id: 01a11485-f0fc-7fd8-ab97-3b7dc3ab87d8
    statement: "The lease tools and the per-request MCP instructions describe the
      recipe for long agent tasks: acquire every resource the task will write up
      front, acquire again as a heartbeat before a long pause such as a build or
      a capture, and release all leases at the end."
  - id: 01a11485-f118-764c-ab2b-1b54b4270625
    statement: The Workbench shows "Locked by <nickname>" with the expiry on a
      leased resource and disables its edit controls with that reason; an Owner
      gets a release action, and a lease refusal shows the same message inline
      and keeps the user's draft.
