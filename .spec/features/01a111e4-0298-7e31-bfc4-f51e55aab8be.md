---
id: 01a111e4-0298-7e31-bfc4-f51e55aab8be
title: Authentication and credentials
summary: "Every `/api/*` and `/mcp` request needs a credential: a browser signs
  in with a single-use invite link and receives an expiring session, an agent
  sends `Authorization: Bearer <token>` (loopback included), and tokens, invites
  and sessions can be created, listed and revoked."
rules:
  - id: 01a11485-ebc1-7a42-ab81-c12b6bb7903f
    statement: Every `/api/*` and `/mcp` request authenticates with a credential,
      loopback included; only the public routes, which carry no Workspace data,
      need none. There is no unauthenticated mode.
  - id: 01a11485-ebdd-70fc-b853-0621caf056b8
    statement: "Every request resolves to exactly one principal or to none, and a
      member's current role is resolved on every request: a credential carries
      no scope of its own, so a role change, removal or revocation applies at
      once."
  - id: 01a11485-ebf7-78e7-9f43-706ca3c964e4
    statement: A browser signs in on `/login` with a single-use invite link or a
      pasted member token and receives a fresh session; a token used to sign in
      stays valid. An invite travels in the URL fragment, which the sign-in page
      removes after reading it.
  - id: 01a11485-ec11-7d76-8099-c1327d7309ac
    statement: "The browser on the host is not implicitly the Owner: it signs in
      like every other browser."
  - id: 01a11485-ec2a-7f06-aa9d-895690f2ca5a
    statement: Agents and scripts authenticate with member tokens, never with a
      browser session, so no web page can drive MCP with ambient browser
      credentials.
  - id: 01a11485-ec45-7f54-b039-2a331c571f9e
    statement: "A credential is valid only on the server of the Workspace whose
      roster issued it: the server looks its public ID up in its own roster and
      verifies it by hash, and the roster hint inside the credential never
      decides validity, so tokens carried over by `uiux access copy` keep
      working."
  - id: 01a11485-ec61-7124-bb2b-8f0f5ebae011
    statement: Only hashes of credentials are stored, and each credential's
      plaintext is shown once, when it is created.
  - id: 01a11485-ec7b-725c-bcc9-e7c6c7cefc11
    statement: A token expires after 90 days unless created with another expiry or
      explicitly with none; an invite is single-use and expires after 24 hours;
      a session ends after 14 days idle or 30 days in total. Tokens, invites and
      sessions all survive server restarts.
  - id: 01a11485-ec95-764f-b06a-044cd83a0b2b
    statement: Invites sign browsers in and are issued only for human members;
      agents get tokens.
  - id: 01a11485-ecae-7f98-b096-39e37aae98df
    statement: A token ends when it is revoked, expires or its member is removed; a
      session ends on sign-out, Owner revocation, member removal or expiry.
      Either takes effect on the server's next request, which is then refused as
      unauthenticated, and the Workbench returns to `/login`.
  - id: 01a11485-ecca-79f2-9af5-314f03912bc4
    statement: A malformed, unknown, expired or revoked credential is refused with
      one failure code, so a response never reveals whether a credential was
      revoked; a credential from another Workspace's roster gets the same code
      with a message that names both rosters.
  - id: 01a11485-ece4-7040-b84f-89480790c649
    statement: Repeated authentication failures from one remote address are
      rate-limited, at 10 per minute.
  - id: 01a11485-ecfe-7194-9052-c86b0f55ad0d
    statement: The rate limit counts distinct failed credentials per address, so one
      stale credential retried by a client does not lock the address out, and
      the in-memory system credentials are never rate-limited.
  - id: 01a11485-ed17-791a-a30e-1b63fa6f16ce
    statement: "Secrets never appear in logs: `Authorization` headers, session
      cookies and credential-shaped strings are redacted."
  - id: 01a11485-ed31-7151-ba49-afe20baa376e
    statement: The server records when each token and session was last used and
      writes that to the roster at most once a minute per credential.
  - id: 01a11485-ed4a-766b-a51c-af2b9ffb1fcb
    statement: A session belongs to the origin where it was created, so `127.0.0.1`,
      `localhost` and a LAN address each need their own sign-in, and two `uiux
      dev` servers on one host never overwrite each other's session; every
      sign-in mints a fresh session.
  - id: 01a11485-ed64-76e9-8371-3ac0e120dbdf
    statement: Formal capture and `uiux publish` read the live server with random,
      per-process system credentials (`system:capture`, `system:publish`) that
      are never members, never stored or logged, never stamped as actors and
      never accepted on `/mcp`; they act with Viewer scope on read routes only.
  - id: 01a11485-ed7e-7866-bec2-6deca0ec6cb1
    statement: The server counts rejected `/mcp` attempts in memory (time, user
      agent and listener), and the Owner sees an "MCP clients without a token"
      notice that offers to create an agent token.
  - id: 01a11485-ed98-7754-a733-343921659920
    statement: The Workbench header shows the signed-in member's nickname and role
      with a sign-out action.
