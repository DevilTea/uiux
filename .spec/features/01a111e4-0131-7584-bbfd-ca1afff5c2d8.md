---
id: 01a111e4-0131-7584-bbfd-ca1afff5c2d8
title: Domain mutations and revision concurrency
summary: "How canonical resources change: only through domain-specific atomic
  mutations under revision concurrency, shared by every transport through one
  application layer, with out-of-band edits detected and a retryable refusal
  when persistence is busy."
rules:
  - id: 01a1144e-508d-7f31-94f9-0c96b0ed4922
    statement: Canonical resources change only through domain-specific mutations,
      each atomic within one resource or domain boundary; a mutation may carry
      several structured operations against that boundary. There is no generic
      file write, arbitrary filesystem write or cross-domain Workspace-wide
      patch, except `uiux workspace apply` (Clause
      01a18120-f64a-73e7-9463-b5039a4041d4).
  - id: 01a1144e-50a1-7125-95ca-f757a8028ae7
    statement: "`/api/*`, `/mcp` and `/preview/*` are separate transport adapters
      over one shared application and domain layer: MCP never calls `/api/*`
      over loopback HTTP, and transport routes never duplicate domain logic."
  - id: 01a1144e-50b5-77f4-9403-493d7914702a
    statement: Edits made to canonical files outside UIUX are detected through
      revisions and validation; such edits bypass mutation-only affordances such
      as reference-impact acknowledgement.
  - id: 01a1144e-50c9-79f7-9530-479feba082fc
    statement: When the persistence lock cannot be acquired within its wait budget,
      the operation changes nothing and fails retryably with the busy refusal of
      the mutation-semantics Contract.
