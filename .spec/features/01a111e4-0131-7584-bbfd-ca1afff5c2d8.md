title: Domain mutations and revision concurrency
summary: "Every canonical change goes through a domain-specific, atomic mutation
  that requires the resource's current opaque `expectedRevision`; a stale
  revision writes nothing and reports the current revision, there is no generic
  file write, and out-of-band edits are detected. `/api/*` and `/mcp` are
  separate transport adapters over one shared application layer (MCP never calls
  `/api/*` over loopback HTTP), so HTTP, MCP and the Workbench share the same
  semantics. When the persistence lock wait budget expires, an operation changes
  nothing and fails retryably with `persistence.busy`: HTTP answers 503 with a
  `Retry-After` header, MCP returns an error result."
