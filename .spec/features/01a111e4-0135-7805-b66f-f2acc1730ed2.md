---
id: 01a111e4-0135-7805-b66f-f2acc1730ed2
title: Reference integrity and destructive changes
summary: "How destructive or identity-changing operations treat references to
  their target: reporting the impact and requiring acknowledgement, staying
  target-local, and keeping dangling or invalid references as repairable
  diagnostics."
rules:
  - id: 01a1144e-50dd-7b92-aa5e-e175e34bf424
    statement: Before deleting a View, UX Flow or authored Asset, renaming a
      Variant, or renaming a viewport or theme key, the normal Workbench or MCP
      operation reports the known affected canonical references and proceeds
      only after the caller explicitly acknowledges that impact.
  - id: 01a1144e-50ef-7219-ae87-bb012dc85f12
    statement: "Such a change stays atomic within its own resource or domain
      boundary: UIUX never cascades it, auto-rebinds references or silently
      rewrites referencing resources."
  - id: 01a1144e-5101-78bb-9748-5bdabb1c013b
    statement: A reference whose target is gone keeps its original target identity
      and is reported as a structured invalid or dangling diagnostic until it is
      explicitly repaired; a Workspace with dangling references is a supported,
      repairable state.
  - id: 01a1144e-5114-7eb7-8cd5-aeb1d356d52f
    statement: UIUX preserves invalid authored data for repair and reports it; it
      never silently drops or rewrites it, and never rebinds a reference
      heuristically by name, type, selector, tree position, geometry or
      similarity.
  - id: 01a172ce-280b-7cec-9ca5-ec189b313ebe
    statement: Deleting a View lists the Review threads anchored in it, the UX Flow
      steps that target it and the Widgets they trigger on, and the View Spec
      references to it; deleting an authored Asset lists the `$asset` bindings
      that would dangle.
  - id: 01a172ce-2b4d-70dc-ab08-bd22c71fd1c7
    statement: "A Variant name that `update_view_structure` removes counts as
      renamed or removed: the impact lists the Review threads that name it and
      the UX Flow steps and View Spec references that target it, and a Variant
      nothing references needs no acknowledgement."
  - id: 01a172ce-2e97-7d83-b175-f0d15f846768
    statement: Removing or renaming a viewport or theme key through
      `update_workspace_settings` needs acknowledgement of the impact list a
      restore of those settings gives; a settings change that removes no key
      needs none.
  - id: 01a172ce-31eb-7b81-afd6-ddd6855cc30e
    statement: When deleting a View, UX Flow or Asset, or removing or renaming a
      viewport or theme key, the Workbench lists the impact the server returns
      and writes only after the person explicitly confirms.
---

Not built: `update_workspace_settings` over MCP or HTTP renames those keys without reference-impact analysis, Variant renames (`update_view_structure`) run without it, and no View, UX Flow or Asset delete operation exists. The `ReferenceImpactAnalyzer` port is declared in `src/application/ports/resources.ts` and used, with the `impact_acknowledgement_required` result, only by `src/application/services/resource-mutations.ts` and `src/application/services/canonical-resources.ts`, which no production service imports. Tracked in issue #75 (https://github.com/DevilTea/uiux/issues/75).
