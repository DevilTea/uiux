id: 01a111e4-02f2-7131-a974-233eb077d10b
title: MCP surface and discovery
summary: "How Agents discover and read a Workspace over MCP: the split between
  Resources and Tools, Resource addressing, compact discovery results, a Tool
  list independent of the caller's permission keys, and the per-request
  instructions."
rules:
  - id: 01a11485-f1ba-7e93-9f3e-081ca9e98495
    statement: MCP Resources are the point-read surface for directly addressable
      read models; discovery, filtering, search and listing are read-only Tools,
      and every mutation and imperative action (such as formal capture, Handoff
      export and Review actions) is a Tool.
  - id: 01a11485-f1d5-74a0-927f-dd59d83ebfee
    statement: "MCP Resource URIs address resources by kind and canonical key within
      the one Workspace the server was started for: they are stable within that
      server, carry no Workspace identity, and are not portable Handoff
      identities."
  - id: 01a11485-f1f1-701d-abb1-272282b96438
    statement: "List and search results are compact and paginated: full bodies and
      large artifacts are read through Resources instead of being copied into
      Tool results."
  - id: 01a11485-f20c-78cb-9984-be1d9c8b0888
    statement: List and search can expand their compact items with more detail or
      selected fields on explicit request.
  - id: 01a11485-f227-7474-9203-1caf9c38c98b
    statement: Each MCP request's server instructions tell the Agent which member it
      is authenticated as and that Review actors and times are stamped by the
      server, so an Agent learns its identity without an extra Tool.
  - id: 01a11485-f247-7f43-abda-bbee6e390892
    statement: Every tool stays registered whatever keys the caller holds, so the
      tool list never changes with keys; a tool the caller's keys do not allow
      refuses with the permission refusal, which names the missing keys.
  - id: 01a11a5e-1ca3-740d-8235-01106d8ffc25
    statement: "The Checkpoint recommendation in the MCP server instructions, worded
      by the MCP interface Contract, is advice only: no Tool requires a
      Checkpoint before `release_lock`."
