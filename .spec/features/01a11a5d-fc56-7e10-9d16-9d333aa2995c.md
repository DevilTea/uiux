---
id: 01a11a5d-fc56-7e10-9d16-9d333aa2995c
title: Workspace version timeline
summary: "The Workspace-wide history of design resources: what a version
  records, which resources and writes it covers, how writes are grouped into
  autosaves, how changes made outside UIUX and recording failures appear, where
  history is stored, and how long host-stored history is kept."
rules:
  - id: 01a11a5d-fdbd-7755-b4e8-2f447692bd46
    statement: "A version is a Workspace-wide snapshot: it records every versioned
      file by content digest and the revision of every versioned resource at one
      instant."
  - id: 01a11a5d-fe15-7ed2-ab74-4616dcc47a28
    statement: A resource's history is the projection of the versions in which that
      resource's revision changed; there are no per-resource revision chains.
  - id: 01a11a5d-fe71-7bbd-a470-776f7d4b2f14
    statement: History versions only the files that the Version history records
      Contract lists.
  - id: 01a11a5d-fec6-7394-8d38-fd10279bd752
    statement: Every successful design operation through `/api/*` or `/mcp`, as the
      Version history records Contract lists them, is recorded as a write event
      that stores exactly the committed bytes by digest.
  - id: 01a11a5d-ff1c-7af9-b69b-cb6dc362143e
    statement: "Write events are grouped into autosaves: an open autosave
      accumulates design writes until one of its closing boundaries occurs."
  - id: 01a11a5d-ff72-7fbb-886f-d1f56f321e98
    statement: An autosave closes when a different actor makes a design write, so
      every autosave has exactly one actor.
  - id: 01a11a5d-ffc6-7c81-bfd1-e4a4fd5847dd
    statement: An autosave closes once no design write has occurred for the idle
      period that the Version history records Contract sets.
  - id: 01a11a5e-0018-7806-95a8-2315da6fdfdf
    statement: An autosave closes once it reaches the duration or event cap that the
      Version history records Contract sets.
  - id: 01a11a5e-0068-7a4b-b4bc-3cb282b4ae5a
    statement: An autosave closes when the Agent that wrote it calls `release_lock`
      with no arguments.
  - id: 01a11a5e-00b9-7bf5-8005-9380a388afb8
    statement: Creating a Checkpoint or starting a restore first closes the open autosave.
  - id: 01a11a5e-010b-75ae-bfd7-7e80d48e8eca
    statement: An open autosave closes at server shutdown, on a best-effort basis,
      or otherwise at the next server start.
  - id: 01a11a5e-015f-79f8-9d29-72674bd748c6
    statement: The autosave boundaries and the host retention are fixed values that
      no Workspace setting, command option or environment variable changes.
  - id: 01a11a5e-01b5-7c2d-8114-15b500d543f5
    statement: Closing an autosave rescans the versioned files under the persistence
      lock and records any difference its events do not explain as a separate
      external version, never as the autosave actor's change.
  - id: 01a11a5e-020b-7716-aa2b-a6e403c59c85
    statement: An autosave whose events leave every resource as it was is still
      recorded, marked as having no net change.
  - id: 01a11a5e-025f-71d7-8d08-63948220de57
    statement: History records the server-stamped actor of every write event and
      version, and the source of every write event and Checkpoint; it accepts no
      caller-supplied actor or time.
  - id: 01a11a5e-02b6-7978-8f1d-9437c14796cb
    statement: A history record keeps the display name stamped at write time;
      renaming or removing a member never rewrites history.
  - id: 01a11a5e-0313-7d86-af79-8eafa1753853
    statement: Changes made outside UIUX, found by comparing the versioned files
      when an autosave closes, when a Checkpoint is created and at server start,
      are recorded as an external version with no member actor.
  - id: 01a11a5e-036d-7955-aa27-4ec036b55938
    statement: "Recording history never fails a design write: the write commits
      first, and when recording then fails the write still succeeds and the
      server logs the failure."
  - id: 01a11a5e-03c9-745e-b23a-bb06b600377d
    statement: A change that a recording failure left unrecorded is recorded at the
      next boundary as an external version flagged as a recording gap.
  - id: 01a11a5e-0422-78fe-b28b-d877417932e9
    statement: A migration's changes appear in the timeline as their own system version.
  - id: 01a11a5e-0485-7a8e-8194-a75c9cf65028
    statement: Autosaves, external and system versions and their write events are
      stored on the host, at the path the Version history records Contract
      gives, never inside the Workspace.
  - id: 01a11a5e-04e2-71fe-8cd7-a4e26f0ff560
    statement: Checkpoints are stored inside the Workspace, at the path the Version
      history records Contract gives, so they travel with it through ordinary
      commits.
  - id: 01a11a5e-0539-7a33-a000-55adde1f72b8
    statement: History never runs Git, reads `.git`, writes to the user's branches
      or refs, or records a Git commit.
  - id: 01a11a5e-0591-7987-a719-e5b40143d3d4
    statement: Each history record is written atomically as one file per version, so
      a crash never leaves a partial record.
  - id: 01a11a5e-05ef-7c25-a035-e94c377fcbd7
    statement: Pruning removes only host-stored autosave and external versions
      beyond the retention that the Version history records Contract sets, and
      never changes the Workspace.
  - id: 01a11a5e-064d-79c9-ade3-220a8f6bfb64
    statement: After pruning, host-stored blobs that no surviving version or
      Checkpoint names are removed by mark-and-sweep.
  - id: 01a11a5e-06a4-7897-9ae1-e2eddd9a2923
    statement: A version whose parent was pruned takes its nearest surviving
      ancestor as parent.
  - id: 01a11a5e-06fb-79c5-8396-d50d08780a6d
    statement: Each version records the provenance of the Adapter set and of the
      Product Kit active when it was taken, in the shapes the Version history
      records Contract gives.
  - id: 01a11a5e-0759-725e-9b87-d1e7a95256e1
    statement: History needs no Workspace `schemaVersion` change or migration step;
      a UIUX build without history ignores both history stores.
  - id: 01a11a5e-07c1-70d6-b4fb-69c99be791e3
    statement: Listing and comparing versions recorded under a recognized schema
      version work in every Workspace schema state, including while migration is
      required or the schema is unsupported.
  - id: 01a11a5e-081c-7149-9345-836ce2267c0a
    statement: A version recorded under an unrecognized schema version is still
      listed, but comparing or restoring it is refused with the diagnostic that
      the Version history records Contract assigns.
  - id: 01a11a5e-0873-7976-8a48-a9a1a00e4b6d
    statement: History never stores Review activity; a timeline that shows Review
      events reads them live from the threads.
  - id: 01a11a5e-08c7-73c1-bc66-3af814a454d6
    statement: History adds no change-event kind; Workbenches re-read the timeline
      on the existing resource change events.
