id: 01a111e4-0171-7cae-a37e-e67ec8deb82f
title: Authored Assets
summary: "Authored Assets: binding them from Views, resolving them for
  execution, replacing their content, validating their media types, and handling
  invalid or unused Assets."
rules:
  - id: 01a115cd-beea-7d7d-bf04-edbf3990104b
    statement: UIUX never treats an arbitrary string or Config value as an Asset
      reference.
  - id: 01a115cd-bf1c-7ab1-933d-c03322035cc5
    statement: For execution UIUX resolves each Asset binding to the value the
      Adapter's renderer consumes at run time, without changing the authored
      binding or Widget Core semantics.
  - id: 01a115cd-bf4e-71ae-9fdb-74cc91862738
    statement: Preview receives only an Asset's resolved run-time value and
      validated media metadata, never a filesystem path.
  - id: 01a115cd-bf91-7d0e-900c-73b4ba2e5095
    statement: Replacing an Asset's content keeps its identity, so existing bindings
      stay valid.
  - id: 01a115cd-bfcb-7615-aa0a-4f46ae0808c6
    statement: A replacement updates the Asset's source content and its metadata
      together in one mutation.
  - id: 01a115cd-c000-722d-b18c-0ad9a7562a99
    statement: A distinct, independently referenced Asset is created with a new
      identity, never by replacing an existing Asset.
  - id: 01a115cd-c036-739a-851f-50eecbd3b21b
    statement: Where determinable, UIUX checks an Asset's declared media type
      against its content signature and filename extension, and a mismatch is an
      Asset validation error.
  - id: 01a115cd-c06c-730f-a979-2491cadfb238
    statement: An Asset binding whose media type or category the Catalog field does
      not accept is diagnosed as a View validation error.
  - id: 01a115cd-c09f-7018-9f52-48b05284f600
    statement: Missing or corrupt Assets, metadata and content mismatches, missing
      binding targets and incompatible bindings are diagnosed without rewriting
      authored data.
  - id: 01a115cd-c0d2-7427-8a95-927b2b3518c9
    statement: A View that binds a missing or invalid Asset cannot render, be
      captured or produce formal Evidence until it is repaired.
  - id: 01a115cd-c106-71d6-b1f8-4d59cab22ad2
    statement: UIUX never substitutes a placeholder or retargets another Asset or
      path for an invalid binding.
  - id: 01a115cd-c13a-7769-b289-2e13417438e5
    statement: An Asset that no View references stays a valid resource and may be
      marked unused, but is never removed automatically.
  - id: 01a167f4-456c-78c5-b7e1-843cb39bcab8
    statement: Writing a View never refuses it for an invalid Asset binding, since a
      binding can become invalid later, when its Asset is deleted.
  - id: 01a167f4-472f-7ae9-8ebb-3075216ad94c
    statement: "The server resolves a View's Asset bindings and reports their
      diagnostics wherever UIUX renders or checks the View: Preview, capture,
      Checks and the View's diagnostics."
  - id: 01a167f4-48f2-7460-8c12-dfc4cda35cd0
    statement: When an Asset that the View of an open Preview binds is replaced or
      deleted, that Preview resolves the View's Asset bindings again.

## Notes

- The Asset directory, metadata and binding shape and the fields that accept a binding are owned by 01a1144e-54c0-7b12-a71e-57774b3448a3, 01a1144e-54d8-7468-b86e-0a700e118101 and 01a1144e-54f0-70c4-a124-e74cd774495c; asset-capable field declarations by 01a115cd-d33a-73df-934f-aab7d0671649; Asset identity by 01a1144e-4f78-7a90-8d52-ace5cdd54dfa; the impact acknowledgement before deleting an Asset by 01a1144e-50dd-7b92-aa5e-e175e34bf424; the Tools by 01a11485-f7ce-7774-96d2-24d2da5356b2; Assets in Handoff by 01a115cd-c82f-7ce1-acd6-480f55774999 and 01a115cd-d67e-701b-af7d-c0dbbc4733cf. The Asset Library layout is an implementation detail (Discussion #9 body).
- Owner ruling 2026-10-07 (batch 5 confirmation): the `asset.*` diagnostic codes are non-normative; code at 85055c1 is authoritative (`src/domain/assets/schema.ts`, `src/assets/bindings.ts`).
- The runtime value, its URL forms, the digest check on Asset content and category matching are owned by the Adapter interface Clauses 01a167f4-3e4e-7af1-b328-30fb52f7f4c5, 01a167f4-401d-7330-ac65-0a900adbccd6, 01a167f4-41f2-70a1-a200-a005d47b12b5 and 01a167f4-43a6-772b-9304-410708912c4e (Discussion #241 owner rulings 2026-10-23). As with `$i18n`, only a top-level Config member takes an `$asset` binding. As of 24d7784 a removed Asset reaches an open Preview through the same change event as a replaced one; no operation deletes an Asset, so only a version restore or an edit outside UIUX removes one, and no browser test removes one. Formal capture also fails a context with `capture.asset_load_failed` when a bound Asset does not load in the Preview, rather than capture it broken (01a115cd-c106-71d6-b1f8-4d59cab22ad2); the code is non-normative. "Does not load" is observed on the network: any request for a bound Asset's URL (either form of 01a167f4-401d-7330-ac65-0a900adbccd6) that answers other than 2xx or 304, or fails, from the Preview page's first request until the screenshot, fails the context whatever asked for it (an `<img>`, a CSS background, a `<video>` poster, a shadow root, `srcset`, an element an Adapter inserts later). Bytes are decode-checked only for an `<img>` in the page's light DOM, before the screenshot; a background, poster or other use whose bytes do not decode is captured as the browser shows it, a request the browser itself aborts (`net::ERR_ABORTED`) is not counted, though an `<img>` that really did not load is still caught by its decode, and a request that starts after the screenshot is not seen. The live Preview checks nothing: this is formal capture only. The digest-qualified Asset URL is revalidated by ETag (`Cache-Control: private, no-cache`), not cached as immutable, because `Content-Type` and `Content-Disposition` come from metadata that the digest does not cover.
- Owner ruling 2026-10-07 (batch 5 confirmation): which signatures and extensions 01a115cd-c036-739a-851f-50eecbd3b21b can determine (PNG, JPEG, GIF, WebP, SVG and PDF signatures; the `.json` and `.txt` extensions) are non-normative; code at 85055c1 is authoritative (`src/domain/assets/schema.ts#L131-L150`).
- Discussion #448 item 3 (owner acceptance https://github.com/DevilTea/uiux/discussions/448#discussioncomment-19325691): Rule 01a115cd-c106 binds UIUX, which never substitutes a placeholder for an invalid binding; it does not forbid an Adapter-authored placeholder State, such as an Image Widget State or a Variant that shows an "image unavailable" content. Before and after images of the Asset detail are two Assets bound by two Image Widgets; a binding has no revision member.
