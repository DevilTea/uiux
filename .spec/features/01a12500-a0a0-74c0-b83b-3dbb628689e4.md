title: Network access
summary: "Reaching the one server from other machines through origins that an
  operator configures: the opt-in and bind policy, how a request's `Host`
  selects its origin and policy, transport and plaintext warnings, startup
  output, and where roster administration is served."
rules:
  - id: 01a12500-a7f3-7da3-b330-f5451f74a2f8
    statement: "Remote access is opt-in: unless an operator configures at least one
      origin, the server accepts requests only on the loopback host names."
  - id: 01a12500-a9c5-74e6-868a-2a6f4a5f3315
    statement: The server refuses to start with a wildcard bind address unless at
      least one origin is configured.
  - id: 01a12500-ab96-73d7-83ec-707a7ab56d49
    statement: Origin-specific policy follows the origin that a request's `Host`
      matched on the Host allowlist, whether that is a loopback origin or a
      configured one.
  - id: 01a12500-ad67-7e14-b375-78a59f822687
    statement: A request whose `Host` is a loopback host name is accepted only from
      a loopback peer address; from any other peer it is refused like a foreign
      `Host`.
  - id: 01a12500-af31-7c3e-b619-78c128f18a1d
    statement: A request on a configured origin is authenticated and authorized like
      a request on a loopback origin, with the same credentials and permission
      keys, except for roster administration.
  - id: 01a12500-b105-7773-822f-359d4dcbd1da
    statement: Roster administration (members, Tokens, invites and sessions) is
      served only on a loopback origin or an `https` configured origin and is
      refused on every other origin as 01a12500-a619-7fa5-b7f6-797adaf52f34
      sets; the host's access commands are unaffected.
  - id: 01a12500-b2db-7083-973d-1bf90a859a5b
    statement: For each configured `http` origin that is not a loopback origin, UIUX
      warns at startup and on that origin's sign-in page that sign-in links,
      session cookies and Tokens cross the network in clear text.
  - id: 01a12500-b4af-7446-a66e-40de3db3dac2
    statement: At startup the server prints its loopback URL and each configured origin.
  - id: 01a12515-9c61-7916-a0d0-4bcf2537dfc9
    statement: The first-run sign-in link is printed for the loopback URL and for
      each configured origin, and every printed link carries the same single-use
      invite.
  - id: 01a12500-b67f-7d35-a3a7-76e2a9a34d69
    statement: Formal capture loads Preview from the internal loopback origin, never
      from a configured origin.
  - id: 01a12500-b84a-7d4e-a52d-5c7e13d78fd0
    statement: "The Workbench works on an `http` origin that is not a secure
      context: copying text and generating identifiers do not depend on
      secure-context-only browser APIs."
  - id: 01a12500-ba1c-7a07-8341-2a8b0691e8c5
    statement: UIUX never derives a request's origin or scheme from forwarding
      headers such as `X-Forwarded-Proto`; a configured origin's scheme comes
      only from its configuration.
  - id: 01a12500-bbed-7aaa-a9bf-869e5e09bd45
    statement: UIUX itself serves plain HTTP only; an `https` configured origin is
      served by a front end that terminates TLS in front of the server.
  - id: 01a12500-bdc9-7f2d-9e29-4a0c4a6d1277
    statement: A sign-in link that the server creates in answer to a request names
      the origin that the request's `Host` matched.

- Proposal Rule N3 holds two assertions; it is recorded as 01a12500-ab96-73d7-83ec-707a7ab56d49 (policy follows the matched origin) and 01a12500-ad67-7e14-b375-78a59f822687 (a loopback `Host` only from a loopback peer). That UIUX serves plain HTTP (01a12500-bbed-7aaa-a9bf-869e5e09bd45) and that sign-in links use the matched origin (01a12500-bdc9-7f2d-9e29-4a0c4a6d1277) come from the proposal's Change 2, which gives them no Rule number.
- Proposal Rule N1 says that without a configured origin the server "binds and accepts loopback only"; the bind half follows from 01a1144e-55ed-7276-8bfe-379be9881357 and 01a12500-a9c5-74e6-868a-2a6f4a5f3315, so 01a12500-a7f3-7da3-b330-f5451f74a2f8 states only acceptance. - A reverse proxy on the same host must forward the client's `Host` (for nginx, `proxy_set_header Host $http_host`, which keeps the port) and must not buffer the event stream. A proxy that rewrites `Host` to the loopback address makes its requests look local: state-changing requests then fail the `Origin` check, but reads and roster administration would be treated as local. This is an operator requirement that the documentation states (Discussion #174, Change 2), not a server Rule.
- Adopted defaults of Discussion #174: a request without an `Origin`, such as an Agent's `/mcp` call, is not refused on any accepted origin (owned by 01a114ec-e38f-78dd-9ba7-983b0f0e85bc); per-client authentication rate limits stay keyed by the connection's peer address (01a11485-f999-7aea-86eb-51121a341c8b), so clients behind a proxy share one limit, and the documentation says so.
- UIUX is served only on a dedicated hostname, never under a path prefix (Discussion #174 owner ruling); the origin format of 01a12500-a436-7368-8347-809e0176cfcc admits no path.
- Owner rulings of 2026-10-10 (https://github.com/DevilTea/uiux/discussions/174#discussioncomment-18848916): `--host` accepts only a loopback or wildcard address (01a12500-a26d-744c-a5ef-4e05fea5c060), so loopback is always reachable and 01a12500-b4af-7446-a66e-40de3db3dac2, 01a12515-9c61-7916-a0d0-4bcf2537dfc9 and 01a12500-b67f-7d35-a3a7-76e2a9a34d69 hold without exception; network exposure is limited by the `--origin` allowlist and the host firewall. Ambiguous origin sets are refused at startup (01a12500-a436-7368-8347-809e0176cfcc). The packaged server run directly stays loopback-only (01a11485-ee85-7844-b82f-fd6a7cebb763); `uiux dev --host/--origin` is the only external surface for configuring origins.
