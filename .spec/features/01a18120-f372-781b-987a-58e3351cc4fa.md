title: Workspace apply
summary: Landing the canonical resources of an authored copy of a Workspace back
  into a Git-tracked Workspace through `uiux workspace apply`, without
  host-local data.
rules:
  - id: 01a18121-0129-735d-adeb-b5a6f973de3c
    statement: An apply copies only what Clauses
      01a18120-f6da-72af-92c4-c77c4889c693 and
      01a18120-f769-7a3e-b234-138587f8d8bc define and never what Clause
      01a18120-f7f0-7903-975a-8c52ef855ab4 excludes.
  - id: 01a18121-01b0-7a68-8e46-b15cd132570e
    statement: "An apply makes the destination's canonical files equal the source's:
      it adds, replaces and removes files until they match."
  - id: 01a18121-023c-749b-8c7e-d84da02846a2
    statement: Review threads are applied only with `--include-reviews`; without it
      the destination's `reviews/` stays unchanged.
  - id: 01a18121-02c4-751d-be6d-576c9a7971d5
    statement: An apply requires the destination Workspace to lie in a Git work tree
      with no change under its directory, and refuses otherwise.
  - id: 01a18121-034e-75a9-92ad-a63caa627323
    statement: An apply plans against the destination's committed content at Git
      `HEAD`, so `git diff` afterwards shows exactly the applied change and `git
      restore` undoes it.
  - id: 01a18121-03d7-7012-8100-ba91ada8d83a
    statement: An apply refuses a Workspace that a running `uiux dev` server holds
      or that has a pending transaction, on either side.
  - id: 01a18121-0464-7c31-8a71-64e02484aae4
    statement: An apply refuses a symbolic link at any path it would read or write.
  - id: 01a18121-04ea-77f5-96a9-4c2c382eb180
    statement: An apply refuses a file inside a copied directory that no canonical
      pattern allows.
  - id: 01a18121-0572-78dc-b1a7-7940c499c0f4
    statement: An apply adds an artifact blob only after verifying its digest and
      never overwrites or removes one.
  - id: 01a18121-05fa-7686-a550-f84fd1d75c4e
    statement: "An apply is atomic under the destination's persistence lock: after a
      crash, recovery leaves the old or the new canonical files, never a mix."
  - id: 01a18121-0682-73e5-b61c-db6bb0c9393d
    statement: An apply with `--check` prints the plan and refusals of the same
      apply and writes nothing.
  - id: 01a18121-0709-7f49-a899-74082c458203
    statement: An apply writes no Checkpoint and no host history, and never changes
      a roster.
  - id: 01a18121-0793-76b8-8bf9-ef36041d3fbb
    statement: An apply copies canonical files as they are and checks no resource
      content; the destination reports their diagnostics as it does for any edit
      made outside UIUX.
  - id: 01a18121-0819-7a7e-8b28-a3c1b3afe347
    statement: "`uiux workspace apply` acts with the host user's file access and
      needs no member credential."

## Notes

- The CLI interface Contract owns the command line, the canonical file set, the artifact blobs, what is never copied and the refusals (01a18120-f64a-73e7-9463-b5039a4041d4, 01a18120-f6da-72af-92c4-c77c4889c693, 01a18120-f769-7a3e-b234-138587f8d8bc, 01a18120-f7f0-7903-975a-8c52ef855ab4, 01a18120-f879-7730-8207-66234a8392cd). `uiux --help` lists the command only once it ships (Clause 01a1144e-5567-70cd-b2bc-19427cf21a20); no Clause owns a command list.
- Settled in the `.spec/` PR of #379: the source's canonical files replace the destination's, so a copy taken before a later commit would revert that commit's changes to the canonical files; there is no three-way merge and no base manifest (owner answer 4), and the pull request's Git diff is the review control. The reviewer should check the plan with `--check` and the diff.
- The proposal's `cp -R .uiux <tmp>/.uiux` does not copy a `spec` provider's directory (for this repository `../.spec`); in such a copy the provider is unavailable and references are unverified (Clause 01a18120-f5b9-75e2-83a6-8048dc5d6fba) until the directory is copied beside it.
- A Workspace that is not in a Git work tree keeps working in every other way (Rule 01a1144e-4f18-7346-90bc-18fad711e63c); only this command needs Git.
