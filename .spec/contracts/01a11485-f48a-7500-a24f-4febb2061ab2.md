- The kit source Tools and the kit file Resources (01a11bb1-b1c2-716f-b611-f8d7b2a934d9, 01a11bb1-b227-77a8-ab57-c287ca5d2bfd, 01a11bb1-b28f-7be6-9d53-3782729297a7, 01a11bb1-b0f1-7e5d-85ad-230c43ad99fb) read only inside `kit/`: a path that is absolute, holds a `..` segment or a control character, or lies in `kit/node_modules/` (in any letter case a case-insensitive file system folds to it) is refused. A symbolic link, or a file below a linked directory, is not listed and is refused by the path checks. As those checks, and any path check after the open, race with a rename, a read binds the open itself to `kit/` (01a13d3e-e253-76b7-84e5-5f3fb167b635): on darwin the open, which never blocks, refuses a link in any component of the path (`O_NOFOLLOW_ANY`); on linux the open file's real path, read from `/proc/self/fd`, must lie inside `kit/` and outside `kit/node_modules/`. The open file must be a regular file with the device and inode of the entry at that real path, and it is read from the open file, so on darwin and linux a link swapped in at any moment is refused, never read. On other platforms, such as win32, the real path is resolved again after the open, a residual race that the Rule's Implementation gap records. A listing opens each directory the same way before and after reading its names and lists a file only when its own open is accepted, with the open file's size. Their results name paths relative to `kit/` only ([code@399e0d6 `src/adapters/kit-source-files.ts#L100-L313`](https://github.com/DevilTea/uiux/blob/399e0d6dbb3924e3ddaadb89f9c32cf7e715f7f6/src/adapters/kit-source-files.ts#L100-L313), [code@399e0d6 `src/adapters/bound-open.ts#L4-L36`](https://github.com/DevilTea/uiux/blob/399e0d6dbb3924e3ddaadb89f9c32cf7e715f7f6/src/adapters/bound-open.ts#L4-L36)). `uiux components` shares this reader without the size limit of 01a13d3e-c4b5-7cc3-a36b-3be6f45cf7ac, which the owner ruling sets for the MCP and Workbench reads only. A refusal for size is `status: "too_large"` with `path` and `limit`; the Workbench mirrors answer it with HTTP 422. As the shapes are code's (checkpoint C above), `get_component_source` returns its copy-record entry as `{ componentDigest, exportedAt, files }`, without `target` and with each `files` key relative to the target directory, because `{ name, withRequires? }` names no target; the Agent adds `target` and prefixes the keys ([code@612fc87 `src/mcp/server.ts#L715-L724`](https://github.com/DevilTea/uiux/blob/612fc879625f6334e726d7ddfad619bcc11e0b36/src/mcp/server.ts#L715-L724)). A declared file it cannot read, or an unreadable `kit/package.json`, refuses with `kit.component_invalid`, a non-normative use of the code that 01a11bb1-8d03-7751-9173-b3c3f1ab7156 owns.
