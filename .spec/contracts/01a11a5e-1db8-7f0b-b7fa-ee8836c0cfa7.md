  and host store paths, the versioned files, the version, Checkpoint, host

## Notes

- Clause 01a11a5e-1e65-7deb-a89e-6ad021248fe0 keeps every blob a host version names in host history (issue #253, https://github.com/DevilTea/uiux/issues/253), so a host version never depends on the artifact store, where a Checkpoint's blobs live (01a11a5e-1e0e-7539-b925-c54dcb1afb55). Artifact cleanup counts only this host's history among its roots (01a14e30-31c0-7289-a944-74af9556eabf); after a Checkpoint is deleted, a cleanup on another clone can remove its blobs, and the deletion reaches this host through a commit. Host versions that an earlier build recorded on a Checkpoint get the blobs they lack copied at the next server start while the artifact store still has them; the start also copies the blobs of the newest Checkpoint, the base the next autosave starts on, so the first autosave close after a pull copies little inside its time bound. A new version may still name a blob neither store has, because recording never fails a write (01a11a5e-036d…); that is logged and the blob stays missing.
- Clause 01a11a5e-2320-7d05-94b9-01e99c0ef7d2 counts write events, one per resource a write changes, and the recorder closes an autosave once it holds at least 200 after a write. Every design write today changes one resource, so an autosave holds at most 200 events; a write that changes several resources (the Product Kit operations of Discussion #139 may) could leave it with more. Recorded from the PR #156 review.
- Why a Contract: these records are persisted inside the Workspace and on the host, are shared by the timeline, checkpoint, comparison and restore Features, are read by Agents and by other UIUX builds, and evolve under their own `historySchemaVersion`, independently of any one Feature.
- Decision 6 calls its physical layout, and #122 calls its Schema delta, non-normative sketches; the table "What `.spec/` records after acceptance" assigns the record shapes, both store paths, `historySchemaVersion`, the name and note limits, the grouping and retention values and the actor types to this Contract, so they are recorded here as the sketch names them. Left to implementation: the file modes of the host store, the format of `open.json` beyond holding the open autosave's events, a `displayName` for system actors, and the field shapes of a semantic diff.
- `<wsid>` is the roster's Workspace ID, 01a11485-f874-73b4-8b0f-2295c21e9085. The Workspace-state diagnostic `workspace.schema_unsupported` is owned by 01a114ec-8931-798b-a550-5a918d013849; 01a11a5e-2434-7342-a3c1-6d63aa74334c only adds the refusal of a version recorded under a schema version other than the current one.
- Checkpoint records are system metadata, not resource files; like formal Evidence records they carry their own format version, so 01a1144e-534c-7087-a504-76075f73df0d is unchanged and the Workspace `schemaVersion` does not move (decision 12).
