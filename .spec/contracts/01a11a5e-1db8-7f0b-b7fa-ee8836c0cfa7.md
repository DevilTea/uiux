title: Version history records
summary: "The persisted records of the Workspace version timeline: the Workspace
  and host store paths, the versioned files, the version, Checkpoint, host
  version and write-event shapes, the actor and source values, the record format
  version, Checkpoint limits and system names, the autosave and retention
  values, the comparison summary statuses and the history diagnostic."

  - id: 01a11a5e-1e0e-7539-b925-c54dcb1afb55
    statement: Each Checkpoint is one canonical JSON file
      `history/checkpoints/<uuid>.json` under the Workspace root
      (`.uiux/history/checkpoints/` below `schemaVersion` 5), where `<uuid>` is
      its full UUID `id`; the file blobs it names are stored in the
      derived-artifact store.
    constrains:
      - 01a11a5d-fc56-7e10-9d16-9d333aa2995c

    statement: "Host history is the directory
      `$UIUX_HOME/workspaces/<wsid>/history/`, with the roster's `<wsid>`: each
      autosave, external or system version is one file `versions/<uuid>.json`,
      the open autosave's events are in `open.json`, and blobs are
      `objects/sha256/<2>/<64>`, the first two and then all 64 hex digits of
      their SHA-256."
    constrains:
      - 01a11a5d-fc56-7e10-9d16-9d333aa2995c
  - id: 01a11a5e-1eba-78ae-a204-52e286a95ddb

      Access presets file and the resource files under `views/`, `flows/`,
      `i18n/` and `assets/`; nothing else is versioned, including a file there
      that belongs to no resource, `reviews/`, the derived-artifact store, the
      Checkpoints, `kit/`, other UIUX runtime files and Adapter code.
    constrains:
      - 01a11a5d-fc56-7e10-9d16-9d333aa2995c
  - id: 01a11a5e-1f14-7a54-ab36-2c1e53bbc995

  - id: 01a11a5e-1f6f-7263-a609-1d60c03d7c2a
    statement: A version record has `historySchemaVersion`, a full UUID `id`,
      `type`, `actor`, `at` (an RFC 3339 UTC timestamp),
      `workspaceSchemaVersion` (the manifest `schemaVersion` it was taken
      under), `resources` and, optionally, `adapters` and `productKit`.
    constrains:
      - 01a11a5d-fc56-7e10-9d16-9d333aa2995c

## Notes

- Clause 01a11a5e-2320-7d05-94b9-01e99c0ef7d2 counts write events, one per resource a write changes, and the recorder closes an autosave once it holds at least 200 after a write. Every design write today changes one resource, so an autosave holds at most 200 events; a write that changes several resources (the Product Kit operations of Discussion #139 may) could leave it with more. Recorded from the PR #156 review.
- Why a Contract: these records are persisted inside the Workspace and on the host, are shared by the timeline, checkpoint, comparison and restore Features, are read by Agents and by other UIUX builds, and evolve under their own `historySchemaVersion`, independently of any one Feature.
- Decision 6 calls its physical layout, and #122 calls its Schema delta, non-normative sketches; the table "What `.spec/` records after acceptance" assigns the record shapes, both store paths, `historySchemaVersion`, the name and note limits, the grouping and retention values and the actor types to this Contract, so they are recorded here as the sketch names them. Left to implementation: the file modes of the host store, the format of `open.json` beyond holding the open autosave's events, a `displayName` for system actors, and the field shapes of a semantic diff.
- `<wsid>` is the roster's Workspace ID, 01a11485-f874-73b4-8b0f-2295c21e9085. The Workspace-state diagnostics `workspace.migration_required` and `workspace.schema_unsupported` are owned by 01a114ec-8931-798b-a550-5a918d013849; 01a11a5e-2434-7342-a3c1-6d63aa74334c only adds the refusal of a version recorded under an unrecognized schema.
- Checkpoint records are system metadata under the reserved `.uiux/` directory (01a1144e-531c-7d71-9bc5-f62340aea55a), not resource files; like formal Evidence records they carry their own format version, so 01a1144e-534c-7087-a504-76075f73df0d is unchanged and the Workspace `schemaVersion` does not move (decision 12).
- Owner ruling 2026-10-08 (question tool, recorded in PR #135): host versions (autosave, external and system) carry no `source`; only write events (01a11a5e-2119-7a5a-951d-58a34e03e8fe) and checkpoints (01a11a5e-2070-7c38-a62e-daae1fd8ac43) record it, so 01a11a5e-20c6-7573-8530-e6fed6d8d4af lists none. Discussion #122 acceptance: https://github.com/DevilTea/uiux/discussions/122#discussioncomment-18807263.
- The write-event operations `composeProductKit`, `updateProductKit` and `updateComponentRegistry` (01a11a5e-216d-7587-8022-66a66f264eee) are named after the Tools of Discussion #139 decision 14, so that Product Kit edits appear on the timeline as write events (decision 12, phase 6) rather than as external changes.
- The implementation conventions that PR #149 (https://github.com/DevilTea/uiux/pull/149) first noted here are formalized as clarifications of the accepted Clauses: the `null` revision of an absent resource in 01a11a5e-2119-7a5a-951d-58a34e03e8fe, the code-point lengths and trimmed stored name in 01a11a5e-2272-795d-8806-1dedf74f7e21, and the unversioned non-resource files in 01a11a5e-1eba-78ae-a204-52e286a95ddb.
