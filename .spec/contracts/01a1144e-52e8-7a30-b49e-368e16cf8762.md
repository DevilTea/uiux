title: Workspace persisted format
summary: "The persisted format of a UIUX Workspace, versioned as a whole by the
  manifest `schemaVersion`: the manifest, the path, file unit and identity of
  every canonical resource kind and of the content-addressed derived-artifact
  store, the canonical JSON shapes of those resources, and the diagnostics of a
  Workspace whose schema is older or unsupported."
clauses:
  - id: 01a1144e-531c-7d71-9bc5-f62340aea55a
    statement: The Workspace manifest is `.uiux/workspace.json` under the Workspace
      root. The `.uiux/` directory is reserved for UIUX system metadata, such as
      the manifest and the derived-artifact store.
    constrains:
      - 01a111e4-011c-7dd3-9913-afa127c17382
  - id: 01a1144e-5336-73e7-84a0-3bcd0cb454f6
    statement: "The manifest is a JSON object holding the Workspace-level settings:
      `schemaVersion`, `i18n`, the ordered `adapters` list and the `viewports`
      and `themes` registries. All five are required; an empty `adapters` list
      or registry is valid."
    constrains:
      - 01a111e4-011c-7dd3-9913-afa127c17382
      - 01a111e4-014f-73a1-8638-c3a58f134cf1
      - 01a111e4-015d-70aa-8098-a2bbe4690dc9
      - 01a111e4-0184-794a-8ede-f7f856ffbe4c
  - id: 01a1144e-534c-7087-a504-76075f73df0d
    statement: "`schemaVersion` is a positive integer and the only schema version in
      a Workspace: resource files carry none and are all decoded under it. The
      current version is 3; versions 1 and 2 are recognized older versions."
    constrains:
      - 01a111e4-0123-7ff7-a650-fd8c690e21d5
  - id: 01a114ec-890a-73a1-808b-cb08087a9597
    statement: The migration steps are `uiux.v1-to-v2`, from `schemaVersion` 1 to 2,
      and `uiux.v2-to-v3`, from 2 to 3.
    constrains:
      - 01a111e4-0123-7ff7-a650-fd8c690e21d5
  - id: 01a1144e-5360-7e16-bd46-b3d7b141cf02
    statement: A field introduced by a later schema version is invalid
      (`schema.unknown_field`) in a Workspace at an earlier version; no version
      treats a later version's field as an optional addition.
    constrains:
      - 01a111e4-0123-7ff7-a650-fd8c690e21d5
  - id: 01a114ec-8931-798b-a550-5a918d013849
    statement: An operation refused because the Workspace needs migration reports
      `workspace.migration_required`, and one refused because its schema is
      `unsupported` reports `workspace.schema_unsupported`. Over HTTP, formal
      capture, Handoff readiness assessment and Handoff export refused with
      `workspace.migration_required` answer 422.
    constrains:
      - 01a111e4-0123-7ff7-a650-fd8c690e21d5
  - id: 01a1144e-5378-77b5-ba82-72ff62e82e3f
    statement: "`i18n` is an object whose required `defaultLocale` is a canonical
      BCP 47 tag. Supported Locales are discovered from Locale files and not
      listed in the manifest, and `i18n` gains further settings only additively,
      through schema evolution."
    constrains:
      - 01a111e4-015d-70aa-8098-a2bbe4690dc9
  - id: 01a1144e-538e-705f-afdc-841028c410e4
    statement: "`adapters` is an ordered array whose order is the canonical
      installation order. Each entry holds a portable module reference (a bare
      package or module specifier, or a `./` specifier relative to the Workspace
      root; never an absolute or resolved path) and an optional JSON-compatible
      Adapter `config`."
    constrains:
      - 01a111e4-014f-73a1-8638-c3a58f134cf1
  - id: 01a1144e-53aa-7eed-a3bb-e937ff066f7e
    statement: "`viewports` maps viewport IDs to presets. A viewport ID is a
      non-empty, case-sensitive, opaque Workspace-local string, and each preset
      records the exact CSS viewport width and height; labels and other metadata
      are separate from identity."
    constrains:
      - 01a111e4-0184-794a-8ede-f7f856ffbe4c
  - id: 01a1144e-53c4-752f-9c46-c4c70b384165
    statement: "`themes` maps theme IDs, which are non-empty, case-sensitive, opaque
      Workspace-local strings, to theme entries; Adapters validate or map those
      IDs but do not own them."
    constrains:
      - 01a111e4-0184-794a-8ede-f7f856ffbe4c
  - id: 01a1144e-53dc-7750-ab57-0e8d38cd9982
    statement: Each View is one file `views/<uuid>.view.json`, where `<uuid>` is the
      View's full UUID and equals its `id`.
    constrains:
      - 01a111e4-011c-7dd3-9913-afa127c17382
      - 01a111e4-013a-798d-a808-3f242a1ac414
  - id: 01a1144e-53f4-7e66-b156-6ed7281f7f32
    statement: A View's top level has exactly `id` (its full UUID), `name` (its
      required display name), an optional single-valued `feature` tag, `ir`,
      `variants` and `spec`; derived timestamps, file paths or filenames and a
      generic `metadata` object are not canonical fields.
    constrains:
      - 01a111e4-013a-798d-a808-3f242a1ac414
  - id: 01a1144e-540b-7bc8-a67f-1255e0e38e70
    statement: "`ir` is the RootShell Widget, with type `RootShell`, ID `root` and
      one Slot, `content`: an ordered array of child Widget sources whose own
      shape the Adapters' Widget plugins define."
    constrains:
      - 01a111e4-013a-798d-a808-3f242a1ac414
  - id: 01a1144e-5423-7def-a70a-7962ad2d2af7
    statement: "`variants` is an object keyed by Variant name, a non-empty string.
      Each entry is `{ state }`, where `state` maps Widget IDs to sparse maps of
      State member overrides (`variants.<name>.state.<widgetId>.<member>`);
      entries carry no UUID and do not repeat the name, and the entry object
      stays open to additive metadata."
    constrains:
      - 01a111e4-013f-7b36-9e39-c57afb0bd320
  - id: 01a1144e-543a-74ba-a4b6-a1804d1d0299
    statement: "`spec` always contains `intent` (a string), `entryConditions`,
      `interactionRules`, `constraints` and `accessibility` (string lists whose
      items carry no IDs), `references` (typed references) and `decisions`
      (Decisions)."
    constrains:
      - 01a111e4-0143-7678-b969-7e1794a3c04f
      - 01a111e4-014a-7438-897b-ba59bc67edca
  - id: 01a1144e-5450-77ca-b9da-eab7e00a46e6
    statement: 'Each `references` entry is a typed reference discriminated by
      `type`: `{ type: "view", viewId, variantName?, relation? }` with a full
      View UUID as `viewId`, or `{ type: "external", uri, label?, relation? }`
      with a non-empty absolute URI of any scheme as `uri`. An optional
      `relation` is a non-empty string, and other `type` values are invalid
      until a schema version adds them.'
    constrains:
      - 01a111e4-0143-7678-b969-7e1794a3c04f
  - id: 01a1144e-5466-7a92-b416-c1e7b060b6c1

  - id: 01a1144e-547c-7ab6-9589-e9a8b8c458c5
    statement: Each Review thread is one file `reviews/<uuid>.review.json`, where
      `<uuid>` equals the thread's `id`.
    constrains:
      - 01a111e4-011c-7dd3-9913-afa127c17382
      - 01a111e4-01bb-783b-9792-a36016cd6c54
  - id: 01a1144e-5491-7217-900c-ded6cbeca233
    statement: "Each Locale is one file `i18n/<locale>.json`, named by its canonical
      BCP 47 tag, holding one flat JSON object that maps literal message keys to
      string values: `.` in a key has no nesting or namespace meaning, and there
      are no per-View, split or merged Locale files."
    constrains:
      - 01a111e4-015d-70aa-8098-a2bbe4690dc9
  - id: 01a1144e-54a8-7a9b-9b3f-a5553c729e89

    constrains:
      - 01a111e4-015d-70aa-8098-a2bbe4690dc9
  - id: 01a1144e-54c0-7b12-a71e-57774b3448a3
    statement: Each authored Asset is one directory `assets/<uuid>/` containing
      `asset.json` and exactly one source-content file; the directory UUID

    constrains:
      - 01a111e4-011c-7dd3-9913-afa127c17382
      - 01a111e4-0171-7cae-a37e-e67ec8deb82f
  - id: 01a1144e-54d8-7468-b86e-0a700e118101
    statement: "`asset.json` records at least the Asset `id`, a required display
      `name`, the source-content filename and the declared `mediaType`;
      references never depend on display, original or content filenames."
    constrains:
      - 01a111e4-0171-7cae-a37e-e67ec8deb82f

## Notes

- Why a Contract: the persisted format crosses every resource Feature and has its own lifecycle (one manifest `schemaVersion`, explicit migration), so it is governed independently of any one Feature.
- Exact JSON property names the Discussions leave open (for example the adapter entry's module-reference key, the viewport preset's dimension keys and the RootShell Slot container) are authoritative in the code types (`src/domain/*/schema.ts`), not restated here.
- Review-thread and UX Flow internal shapes and the `spec.decisions` item shape are added as Clauses by later import batches (Review and Flow).
