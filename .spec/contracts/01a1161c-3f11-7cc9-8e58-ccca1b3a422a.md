title: Preview cross-iframe protocol
summary: "The protocol between the Workbench and its Preview iframe: the wire
  channel and transport batches, the message envelope, field encoding and
  correlation context, Preview session and runtime generation identities and
  their gates, the capability handshake, and the geometry stream, targeting and
  Widget Event messages."
clauses:
  - id: 01a1161c-3f6b-7a54-aed0-10f035a71799
    statement: "Protocol traffic travels by `postMessage` between the Workbench
      document and its Preview iframe as posts on the channel
      `uiux:preview:wire`: `{ channel, message }` with one envelope, or a batch
      `{ channel, messages }` with 1 to 256 envelopes and no other member. A
      receiver drops any other post on that channel whole."
  - id: 01a1161c-3fa7-71a1-9c20-48f96e5f7d19
    statement: "A batch adds no identity, sequence, count or context of its own: the
      receiver passes each inner envelope, in order and independently, through
      the validation and gates of a single post, so an invalid envelope is
      rejected alone and a batch means exactly what the same envelopes sent as
      consecutive single posts mean."
  - id: 01a1161c-3fe9-7b4b-ac66-efbfcca4eb30
    statement: "Each side posts protocol traffic with its own origin as the target
      origin, never `*`, and accepts a post only when its origin equals its own
      and its source is the peer window: the current Preview iframe's window for
      the Workbench, the parent window for the Preview document."
  - id: 01a1161c-4028-7f0e-90f2-181b54e658ea
    statement: "Every protocol message is an envelope `{ type, context, payload }`:
      `type` is a non-empty, stable string from which the receiver selects the
      message schema, never inferred from the payload or a numeric code;
      `context` holds the shared correlation identities; `payload` holds all
      message-specific data, even when it is empty."
  - id: 01a1161c-4063-7e53-a529-a2d38bdf52a9
    statement: Required fields are always present, and an optional field that does
      not apply is omitted, never sent as `null` or another sentinel. A receiver
      ignores unknown fields of a known `type` while validating every known
      field; a field that a receiver must understand for correctness needs a
      capability or protocol-version gate.
  - id: 01a1161c-40a0-7115-960a-5244f8a4084f
    statement: "The `context` key set is closed: `previewSessionId`,
      `runtimeGenerationId`, `viewId`, `variantId`, `runtimeContextVersion`,
      `navigationRequestId`, `widgetId` and `geometryRevision`, each present
      only when it applies to the message; `variantId` carries the Variant name
      and is omitted for the base state. Work-specific identities, such as
      contour-work sequences, snapshot versions, region IDs and interaction IDs,
      belong in `payload`."
  - id: 01a1161c-40de-705c-8821-df94c85e20cd
    statement: "`previewSessionId` is a non-empty opaque string that the Workbench
      generates fresh for each Preview session and gives the Preview document at
      bootstrap; the runtime only echoes it, and both sides compare it by
      equality, never by order."
    constrains:
      - 01a111e4-0230-7cd4-8870-cb5c4e7139e3
  - id: 01a1161c-4119-712d-8785-7d8155c0ceee
    statement: "`runtimeGenerationId` is a non-empty opaque string that the runtime
      generates fresh for each runtime generation; the Workbench never allocates
      it and compares it by equality, never by order."
    constrains:
      - 01a111e4-0230-7cd4-8870-cb5c4e7139e3
  - id: 01a1161c-4154-7de9-9dc5-622d21438a47
    statement: A generation ID is retired for the rest of its Preview session once
      its generation ends, even if it was never acknowledged; a generation that
      reuses a retired ID is a non-recoverable protocol violation, and the
      Workbench rejects it and all its traffic.
    constrains:
      - 01a111e4-0230-7cd4-8870-cb5c4e7139e3
  - id: 01a1161c-418f-799c-944d-23a1e17e4f19
    statement: "Each side checks a received message's correlation outermost first:
      the Preview session, then the runtime generation, then the remaining
      identities the message carries. The first mismatch makes the message
      stale."
  - id: 01a1161c-41ce-7839-8e27-c49161a42369
    statement: "A message that fails a correlation gate is stale and is discarded
      without effect: it is never staged for later, never adopted, never
      reactivates its generation and never by itself fails the current session
      or generation."
  - id: 01a1161c-420a-7b55-bccb-c64ab28e66e1
    statement: The handshake uses `capability.declare`, sent by the runtime with
      `payload` `{ protocolVersion, features }`, where `protocolVersion` is the
      protocol version the runtime implements, currently 1, and
      `capability.ack`, sent by the Workbench with `payload` `{}`. Their
      `context` carries only `previewSessionId` and `runtimeGenerationId`.
    constrains:
      - 01a111e4-0230-7cd4-8870-cb5c4e7139e3
  - id: 01a1161c-4246-708c-9ab9-60e079b9d475
    statement: "`features` is the generation's set of feature strings. Protocol
      version 1 defines `geometry`, `geometry.multi-target` and `widget.events`;
      adding an optional feature leaves `protocolVersion` unchanged, and the
      Workbench ignores a feature it does not know."
    constrains:
      - 01a111e4-0230-7cd4-8870-cb5c4e7139e3
  - id: 01a1161c-4283-70b7-b487-e81bc28ce875
    statement: For each generation the runtime first sends `capability.declare`,
      echoing the session ID it was given. Until the runtime has received the
      matching `capability.ack` for that session and generation, neither side
      sends any other message type for that generation, and a receiver rejects
      any that arrive.
    constrains:
      - 01a111e4-0230-7cd4-8870-cb5c4e7139e3
  - id: 01a1161c-42bf-7f97-8593-a82bd55665a8
    statement: The first valid declaration of a generation pins its capability set
      before any acknowledgement. A later identical declaration in that
      generation is an idempotent duplicate that the Workbench answers with the
      same acknowledgement; a differing one makes the generation
      protocol-invalid, and the Workbench never acknowledges it.
    constrains:
      - 01a111e4-0230-7cd4-8870-cb5c4e7139e3
  - id: 01a1161c-42fc-7e45-a3d7-e9a82a588950
    statement: "A declaration without an acknowledgement keeps its generation, and
      the runtime may resend it unchanged; duplicate matching acknowledgements
      are idempotent and never acknowledged in turn. The protocol has no
      connection epoch, reconnect ID, handshake attempt ID, retry token or
      capability digest: the session and generation identify the handshake and
      its pinned capabilities."
    constrains:
      - 01a111e4-0230-7cd4-8870-cb5c4e7139e3
  - id: 01a1161c-4339-7614-ba65-6f21e37cd1a0
    statement: A reloaded Preview document or a restarted runtime is a new
      generation with its own declaration and acknowledgement, and a retired
      generation is never revived. A pure transport reconnect keeps the session,
      the generation, its handshake state and in-flight requests, whose
      responses are accepted when they still pass the gates.
    constrains:
      - 01a111e4-0230-7cd4-8870-cb5c4e7139e3
  - id: 01a1161c-4379-76a7-b15e-984a9b7e3309
    statement: A new generation invalidates every geometry revision, region ID,
      contour-cache snapshot version and contour-work sequence of the previous
      generation; equal values in two generations never identify the same thing.
    constrains:
      - 01a111e4-0230-7cd4-8870-cb5c4e7139e3
  - id: 01a11658-28e5-7c4a-8608-64cdcbfaf33f
    statement: "Widget geometry uses three messages: `geometry.acquire.request` and
      `geometry.release` from the Workbench, each with `payload` `{}` and no
      `geometryRevision`, and `geometry.acquire.response` from the runtime, with
      `context.geometryRevision` and `payload` `{ rect, regions }`, where `rect`
      is `{ x, y, width, height }`. All three carry `navigationRequestId` and
      `widgetId`."
    constrains:
      - 01a111e4-023c-7cd5-8c98-3ca18eaab504
      - 01a111e4-0258-7bd1-805a-b270040f08ba
  - id: 01a11658-292d-7bfe-9f5a-6ae6c3641d40
    statement: Geometry on the wire, including a commit's click point, is in
      unscaled CSS pixels of the iframe content viewport with (0, 0) at its
      top-left corner, after the Preview's own scrolling; it excludes the iframe
      element's border, its placement and every Workbench scale, zoom or
      transform.
    constrains:
      - 01a111e4-023c-7cd5-8c98-3ca18eaab504
      - 01a111e4-024a-724e-ad90-bb6bcfb564da

  - id: 01a11658-2972-7fe3-9223-67c74e5f6816
    statement: "`navigationRequestId` is the Workbench-minted identity of one
      geometry stream, whatever consumes it: a non-empty opaque string compared
      by equality only. The Workbench mints a fresh one for every stream it
      opens and never reuses one within a runtime generation, so a report for a
      released or superseded stream is recognizably stale."
    constrains:
      - 01a111e4-023c-7cd5-8c98-3ca18eaab504
      - 01a111e4-0258-7bd1-805a-b270040f08ba
  - id: 01a11658-29b8-74fe-8c60-e959c4020212
    statement: "`geometry.acquire.request` opens a stream for one Widget. A new
      request for a Widget with an open stream supersedes that stream at once,
      and streams for different Widgets coexist. `geometry.release` ends a
      stream one-way, unacknowledged and best-effort, and a lost release is no
      failure. Every stream also ends, without a release, when the runtime
      generation, View, Variant, runtime context or Preview session changes."
    constrains:
      - 01a111e4-023c-7cd5-8c98-3ca18eaab504
      - 01a111e4-0258-7bd1-805a-b270040f08ba
  - id: 01a11658-29fd-7a44-8e90-4da7cfe3d819
    statement: After its first report, a stream reports again only when the Widget's
      `rect` or `regions` change, each time with an advanced revision. The
      runtime coalesces changes to at most one report per stream per animation
      frame, never throttles below that, and sends no report and advances no
      revision while nothing changes.
    constrains:
      - 01a111e4-023c-7cd5-8c98-3ca18eaab504
      - 01a111e4-0258-7bd1-805a-b270040f08ba
  - id: 01a11658-2a43-7934-a36a-bcd894ea9b09
    statement: "Each `geometry.acquire.response` holds the full `rect` and the
      complete visible-region set of one Widget at one revision and is accepted
      or rejected as a whole: a missing, duplicated or malformed region rejects
      the entire report, and `rect` and `regions` never belong to different
      revisions."
    constrains:
      - 01a111e4-023c-7cd5-8c98-3ca18eaab504
      - 01a111e4-0258-7bd1-805a-b270040f08ba
  - id: 01a11658-2a8a-71ca-97ea-4e1a5771014d
    statement: "`geometryRevision` is a JSON safe integer with its own increasing

      true change of a Widget's geometry, including one caused by scrolling,
      advances it; the protocol has no scroll epoch or scroll-offset field."
    constrains:
      - 01a111e4-023c-7cd5-8c98-3ca18eaab504
      - 01a111e4-0258-7bd1-805a-b270040f08ba
  - id: 01a11658-2acf-7187-9f35-aa646342788d
    statement: Beyond the shared gates, a geometry report is accepted only when its
      `navigationRequestId` is the open stream of its `widgetId` and its
      revision exceeds the last one accepted for that Widget in the generation,
      which also covers the first report of a superseding stream. A report
      failing either check is stale for its own stream only.
    constrains:
      - 01a111e4-023c-7cd5-8c98-3ca18eaab504

    statement: "A Widget without a rendered box keeps its stream open and is

      - 01a111e4-023c-7cd5-8c98-3ca18eaab504

    statement: A runtime that declares the optional `geometry.multi-target` supports
      at least 64 concurrent streams and `geometry.release`; with it the
      Workbench opens at most 64 streams per runtime generation
      (`MAX_TRACKED_WIDGETS`), counting every consumer, and the runtime may
      silently ignore requests beyond that. Without it, the Workbench opens at
      most one stream and never sends `geometry.release`.
    constrains:
      - 01a111e4-023c-7cd5-8c98-3ca18eaab504

  - id: 01a11658-2b9f-7f1d-8ffa-12403fa7ea27
    statement: Targeting uses `targeting.enter` (`payload` `{
      targetingInteractionId, purpose }`, `purpose` `inspection` or
      `comment-range`) and `targeting.exit` (`payload` `{}`) from the Workbench,
      and `targeting.hover` (optional `context.widgetId`; `payload` `{
      targetingInteractionId, pointerType? }`, `mouse` or `pen`),
      `targeting.select` (`context.widgetId`; `payload` `{
      targetingInteractionId, point? }`) and `targeting.escape` (`payload` `{
      targetingInteractionId }`) from the runtime. They never carry
      `navigationRequestId` or `geometryRevision` and need no capability
      feature.
    constrains:
      - 01a111e4-024a-724e-ad90-bb6bcfb564da
  - id: 01a11658-2be5-7624-8b73-6f09d765e955
    statement: "`targetingInteractionId` is a fresh, non-empty opaque string that
      the Workbench mints whenever it enters or replaces an interaction,
      compared by equality only, with no order or persistence; a new one
      supersedes the previous one at once. Every runtime targeting message
      echoes it: one lacking session, generation or interaction identity is
      invalid, and one whose identities are not the active ones is stale."
    constrains:
      - 01a111e4-024a-724e-ad90-bb6bcfb564da
  - id: 01a11658-2c29-78c8-88af-f08ac9b8ec98
    statement: Unlike other messages, a targeting message with a `payload` member
      its type does not define is invalid. `point` is `{ x, y }` of finite
      numbers, sent only on a `comment-range` commit, and the Workbench ignores
      it on an `inspection` commit. `targeting.hover` is sent only when the
      candidate changes, never for touch, and `targeting.escape` only during
      `comment-range`.
    constrains:
      - 01a111e4-024a-724e-ad90-bb6bcfb564da
  - id: 01a11658-2c72-7b1a-8030-cd2e0ad95294
    statement: Widget Event reporting uses `widget.event.arm` from the Workbench
      (`context` without `widgetId`; `payload` `{ armId, triggers }`, at most
      256 unique `{ widgetId, event }` pairs, `MAX_ARMED_TRIGGERS`, an empty
      list disarming) and `widget.event.occurrence` from the runtime (`context`
      with `widgetId`; `payload` `{ armId, event }`). Neither carries
      `navigationRequestId` or `geometryRevision`.
    constrains:
      - 01a111e4-0207-7859-a8e0-65bc2fc82289
  - id: 01a11658-2cb9-70ea-a850-0bf01e2a6b55
    statement: An arm replaces the previous one entirely and is never acknowledged.
      The runtime applies it only when its View and Variant equal the runtime's
      render context, and a View or Variant change clears it. `armId` is fresh
      for every arm, never reused within a runtime generation and compared by
      equality only; after one occurrence an arm is spent, and the runtime
      reports nothing more until a new arm arrives.
    constrains:
      - 01a111e4-0207-7859-a8e0-65bc2fc82289
      - 01a111e4-024a-724e-ad90-bb6bcfb564da
  - id: 01a11658-2cff-70bf-8b0e-0748bf7f64a4
    statement: A runtime that declares the optional `widget.events` observes only
      armed pairs, passively, so emission, listener order and the exceptions a
      plugin sees stay unchanged; it ignores armed pairs its Runtime lacks,
      reports nothing emitted before its Runtime finished mounting, keeps the
      arm across Runtime instance swaps, and reports an occurrence whatever
      caused it. A formal-capture Preview is never armed.
    constrains:
      - 01a111e4-0207-7859-a8e0-65bc2fc82289
  - id: 01a11658-2d47-7e88-9ed8-33be3a2117fe
    statement: "The occurrence `payload` is closed for senders: a runtime sends no
      member besides `armId` and `event`, so never arguments, argument counts or
      types, hashes, DOM targets, coordinates, key codes, text or timestamps; a
      receiver still ignores unknown additive members."
    constrains:
      - 01a111e4-0207-7859-a8e0-65bc2fc82289
  - id: 01a11658-2d90-7075-8191-beb161365eae
    statement: After the transport, session, generation and acknowledgement gates,
      the Workbench accepts an occurrence only when its generation declared
      `widget.events`, its View and Variant are current, it carries the current
      `armId`, no targeting interaction is active, its generation is bound to
      the open step entry, and its trigger is armed and resolves to exactly one
      transition; any other occurrence is dropped, never a protocol failure.
      Each Prototype step entry is one runtime generation.
    constrains:
      - 01a111e4-0207-7859-a8e0-65bc2fc82289
  - id: 01a11658-2dd8-7a20-865f-845175476f50
    statement: Entering any targeting interaction first sends a disarm, an arm with
      no triggers and a fresh `armId`, then `targeting.enter`, on the same
      ordered channel; replacing an interaction keeps the runtime disarmed. An
      exit with no successor interaction is followed by an arm with a fresh
      `armId` while the same step entry is still open.
